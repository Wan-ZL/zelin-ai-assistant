# Adapters — how the three sensors read a project

"Wired" = `run_ui.py` builds and runs it; "table only" = run by hand, paste into Notes. `detect_ui.py` is the only place that looks at the world; every plan is built from its JSON. Project instruments beat skill fallbacks and are called verbatim; the report names which one ran.

## STRUCTURE

| Adapter | Detection | What it emits | `producer.mode` |
|---|---|---|---|
| `web-source` (`inventory_a11y.extract_source`) | `*.tsx/.jsx/.vue/.svelte` (root = common dir, e.g. `web/src`) or `*.html` when no framework source | one item per element with a role: explicit `role=`, `input[type]` table, HTML implicit roles; accessible name = `aria-label` > `aria-labelledby` > `alt` > `<label for|htmlFor>` > text content > `title`; bilingual `text("zh","en")` / `t(…)` / `L(…)` literals keep both halves; `{expr}` → `{dynamic}`; component-only children → `{dynamic}`; `hidden`/`aria-hidden`/inline `display:none` → hidden state; literal `disabled`, `tabindex="-1"`, `inert` → not focusable; `{flags.x && …}` / `data-gated` → `gated`; `data-parity-id` → `pin`; `data-side` on a landmark → `topology.side`; landmark/list/region nesting → `topology.parent`; same id across the whole inventory → `#2, #3…` and `count` | source |
| `project:extract_native_inventory` (`inventory_a11y.normalize_native`) | `ui/parity/native-inventory.json` (frozen) — or `scripts/ui/extract_native_inventory.py --write --out <report>/inventory/…` when only the producer exists (never into `ui/`) | `controls[] → items` (native role table: button/alert-button/menu → button, toggle → switch, textfield → textbox, picker → combobox, menu-item → menuitem, label/copy/help → static), `rail → landmark navigation` with `side` + one `link` per item (shortcut kept), `lanes → list` landmarks with `side = rail`, `screens → heading`, `shortcuts → menuitem`, `settings_keys → switch`, `theme_layout → dims.default_theme + layout_pointers` | frozen |
| `web-playwright` (`probes/driver.cjs`) | `node` on PATH and `require.resolve("playwright")` (or `@playwright/test` → `playwright-core`) succeeds in the web package dir; a launch recipe | per screen × scene × theme × viewport × language: nodes (role, name, name_source, visible/hidden_by, focusable, bbox, computed color/background/font/radius/padding, contrast over the effective background), landmarks with `side` relative to `<main>`, Tab walk (node idx → item id), overflow, computed value of every declared custom property, geometry bboxes for `config.geometry`, first-frame theme under both emulations, axe violations when `axe-core` resolves, masked screenshot | runtime |
| Swift source without the project extractor | any `*.swift` | UNAVAILABLE "needs project adapter" — the skill ships no Swift heuristics | — |
| macOS AX runtime, iOS `idb`, Flutter, Android | — | table only in 0.1.0 (the schema and role table admit them) | — |

Screen mapping: `config.screens[].source` globs → `id`; otherwise `pages/<Name>Page.tsx → name`, `components/<dir>/… → dir`, `<stem>.html → stem`. The pairing key uses the screen **family** (`board.card → board`).

## TOKENS

| Adapter | Detection | What it emits | mode |
|---|---|---|---|
| `tokens-css` (`tokens.extract_css_tokens`) | `tokens.css` / `variables.css` / `theme.css` with `--vars`, else any css with `:root` + `--vars` (max 2) | per theme scope (`:root` → light, `[data-theme="x"]` → x, `@media (prefers-color-scheme: dark) { :root… }` → dark): `{path: {$type, $value, source, var}}`; families by prefix (`--type-* → typography`, `--radius-*`, `--space-*`/`--spacing-*`/`--gap-*` → spacing, `--shadow-*`, `--native-layout-* → layout.<group>.<name>`, `--native-color-*`, colors by parse) or `config.tokens.categories`; `font` shorthand → `{weight, size, line, family}`; `var(--x)` resolved one level; `default_theme.declared` from `index.html` (`dataset.theme = "x"` → fixed) or `color-scheme` + prefers block → system; literal census over component css dirs (color / border-radius / font-size bypassing `var(--…)`) | source |
| `design-tokens-json` (`tokens.load_design_tokens`) | `ui/tokens/native-tokens.json` (frozen) or any W3C design-tokens file | flattened dotted paths; `$value: {light, dark}` split per theme; `theme.default` / `theme.follows_system` → declared default | frozen |
| `type-scale-ts` | `typeScale.ts` | `token: "--type-x", font: "…"` rows → `type_scale` | source |
| runtime computed | the driver | `tokens_observed[theme][var] = computed value` → `tokens_runtime` drift | runtime |

Geometry map (`config.geometry`; built-in default for this repo when `ui/tokens/` exists): `layout.lane.width → board / role=list / width`, `layout.rail.default_width → * / role=navigation / width`, `layout.lane.gap → board / role=list / gap`, `layout.strip.width → board / [data-strip] / width`. Each path also carries `css_selectors` = the selectors of component-CSS rules that consume `var(--native-layout-…)`; the driver measures those when the role/selector matches nothing, so wiring a token into CSS makes its geometry measurable without hand-written selectors. Runtime: bbox measure vs the reference token value (± `geometry_tolerance_px`); when the subject declares the same value but renders differently the row says "declared matches, rendered does not". A path with no bbox is never a pass: token consumed nowhere → MISSING (substituted: nothing renders it); consumed but unmatched at runtime → UNAVAILABLE and the layer is `unavailable`.

## Launch (project data — `ui/parity/config.json [launch]`)

`server` argv (placeholders `{py}`), `seed` argv (`{py} {home} {scene}`), `ready` path, `marker`, `home_env`, `port_env`, `needs` (adapter keys that must exist, e.g. `web_dist`), `flags_all_on`. The server process gets `home_env` **and** `HOME` pointed at the temp home (same as `web/e2e/demoServer.ts`: `~/.claude/settings.json` reads as absent, no developer path or model name reaches a screenshot). Two marker forms: `{"path": "/api/health", "expr": ".demo == true"}` (the app reports a demo flag) or the **seed echo** `{"path": "/api/board", "echo": {"file": "state/dashboard.json", "keys": ["generated_at", "id"]}}` — every listed key's scalar values in the file the skill just seeded must be non-empty and equal, as a set, to the values in the app's answer; real data cannot echo the seed's ids and timestamp. This repo's built-in default: `python3 -m server` with `scripts/demo_seed.py <home> --scene <scene>` on a free `ZAI_PORT`, temp `AIASSISTANT_HOME`, seed-echo marker on `/api/board` (the server has no demo flag), needs `web/dist/index.html`. The skill never reads the live `state/`.

## Contract the parity PR (`feat/ui-parity-contract`) must satisfy for the `native` slots to flip from "absent" to "present"

- `scripts/ui/extract_native_inventory.py --write --out <file>` and `extract_native_tokens.py --write --out <file>`: deterministic sorted-key JSON, exit 0/1/2, fields add-only, ids in the single-colon grammar with `#n` ordinals, `rail.side`, `lanes.items[].rail`, `theme_layout[]` with `theme:default` and `layout:*` pointers.
- `scripts/ui/parity_check.py --check --report <dir> --report-json <dir>/report.json --report-md <dir>/report.md` (as landed in #162: `--report DIR` writes only the verdict text; the JSON / MD default to the project's `ui/parity/report.*`, so the skill passes all three paths into the report dir and never rewrites the project tree) writes `items {id: PRESENT|MISSING|PENDING|STALE|WAIVED}` + `counts`, reading `ui/parity/{pending,waivers}.txt`; `--write-pending` is the project's sole ledger writer. Its probe clicks every button (dialog copy, expanded details) — the skill's runtime tree is the rest state, so on `control:*` ids the two can disagree (`parity_disagreement` lists both); on `shortcut:*` / `setting:*` the skill adopts the gate's verdict (references/pairing.md).
- `ui/parity/config.json` (optional) may declare `references`, `screens`, `launch`, `dims`, `geometry`, `masks`, `goldens.dir`, `tokens.{categories,contrast_pairs,only_dirs}`, `rules`, `thresholds`; `qa/gates.toml [ui]` wins over `thresholds`.
