- **自动部署不再跨大版本升级（CONTRACT §56.3 大版本边界追记、§26 追记；lite 2.0 的前置补丁）**：2.0 是另一棵产品树（没有 actd），1.x 的 `scripts/auto-deploy.sh` 若把它 fast-forward 进来，就绪等待与 doctor 闸门会用旧标准判新树，结果是回滚 + 标记 sha，每台 1.x 机器每 10 分钟一次。自本版起：origin/main 上可达的最高 `v*` tag 的 major 大于本机版本 → 不 ff、不装、不问 CI，`deploy_state` 写 `major_boundary`（detail 点名 tag 与手动命令），每个 tag 只通知一次，`--force` 同样不跨；doctor `auto-deploy` 行 WARN 并给出手动升级命令。更新检查的 payload（`update_available` 投影与 CLI）add-only 多一个 `manual_upgrade` 标记；「一键更新」（`POST /api/update/install`）遇到新的大版本回 409 `manual_upgrade`，不再 kickstart。升级到 2.0 只走手动：在 repo 里 `git fetch --tags origin && git checkout v2.0.0 && bash install.sh`。
- **`tests/test_secrets.py` 不再可能写进真实的 `config/secrets/`**：每个测试改用自己的临时 `SECRETS_DIR`，原先在每个测试前清空 `SECRETS_DIR` 的 setUp 一并去掉（`config.HOME` 一旦解析到真 checkout，它会删掉真的 token 文件）。
