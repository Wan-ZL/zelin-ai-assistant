- **雷达不再对 iCloud 驱逐的 note 放弃（§47.5，R-202/R-204）**：Obsidian vault 住在 iCloud Drive 时，「优化 Mac 存储」会把冷 note 驱逐成 dataless 占位，cron 语境下读它报 `[Errno 11] Resource deadlock avoided`；老雷达把它当毒 note 烧满重试额度进 `gave_up` 并铸放弃诊断卡（2026-08 三篇 screenpipe note），而 `_is_due` 对「放弃且 mtime 未变」的条目永久跳过——文件几分钟后读得动了也再没人读。现在读前探测 `SF_DATALESS`、`brctl download` 把文件真拉回本机再读（重开 `open()` 在 cron 语境下还是 EDEADLK）；仍不在本机的 note 记 `deferred`：额度单独放宽、不算提取故障、health 不报 `extract_failed`，但**仍有终点**——烧完照常放弃留痕。已经放弃的同类案底每轮载入时复活一次（`rearmed`），换了 vault 根（mirror 模式）的老案底按同名 note 搬到当前根上再重读；本轮读不到的案底一律保留 `gave_up` 留痕。等下载与催下载共用一本每轮预算（守护进程卡死时也不会攥着 `state/radar.lock` 几小时），而驱逐位只决定催不催——催完照样真读一次，读得到的 note 不会被探针判成「还没在本机」。
