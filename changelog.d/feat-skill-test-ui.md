- **`skills/test-ui` 测 UI skill（v0.1.0）**：test-code 的姐妹尺子——用三个传感器对照一个 REFERENCE 量 UI：STRUCTURE（可达性树清单：每屏的 roles / names / topology；app 起不来时退到源提取）、TOKENS（设计语言：颜色、字号梯、间距、圆角、布局几何、默认主题——computed styles 与源常量）、VISUAL（demo 数据截图 vs golden 的感知差）。两种模式一套管线：`--against native|git:<ref>|dir:<path>|url:…|app:<argv>|inventory:<file>`（迁移对齐）与 `--against design-system`（项目 tokens + WCAG）。同一套 doctrine：五档（第 5 档无时限）、问一次（tier 单选 + 检查多选）、确定性脚本判决、一份诚实报告（report.md + report.json：PRESENT / MISSING / CHANGED / WAIVED、N-A / UNAVAILABLE / SUBSTITUTED 三分、fix-first 七级、结构性盲区、反作弊机械执法）。账本（`ui/parity/{pending,waivers,aliases}.txt`）住项目、只许缩，skill 永不写（`--propose-pending` / `--propose-goldens` 只落报告目录）。本 repo 的 parity 契约脚本在场时逐字调用（`project_parity` / `project_visual`），缺席时用 skill 的 stdlib 提取器并在 references/adapters.md 写明它们要满足的接口。第 4 / 5 档的层 0.1.0 只诚实标 UNAVAILABLE；runtime（Playwright）层在本机同样 UNAVAILABLE 直到 `web/` 装上 `@playwright/test`。`.gitignore` 加 `.test-ui/reports/`、`.test-ui/cache/`；skill 脚本进夜间变异靶区。
