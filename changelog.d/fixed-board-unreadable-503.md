- **A board file the service cannot read no longer reports as "not found."** When `state/dashboard.json` exists but this process is denied the read (permissions, I/O, an unreadable external volume), `GET /api/board` now answers 503 `BOARD_UNREADABLE` carrying the real `errno` and `strerror` instead of the 404 "dashboard.json not found — is actd pointed at this AIASSISTANT_HOME?" that had hidden the cause for weeks; the board page says the file cannot be read, keeps the last board it loaded successfully, and no longer offers "Generate now" (seeding would have replaced the unreadable file with a possibly empty board). `GET /api/health` gains an add-only `dashboard_error` key with the same `path` / `errno` / `strerror`, so the setup wizard's "First data" row and the settings diagnostics panel show the number needed to fix the operating-system cause, and the pipeline banner no longer claims a board that exists "was never generated" (CONTRACT §49 / §47.4 / §54.2 追记 2026-09-18, issue #423).
