- **一条命令装到能用：`scripts/bootstrap.sh` + macOS CI 验收（CONTRACT §69 新增；owner 2026-09-02 验收标准「在另一台电脑上起一个空白环境……就能够直接使用」，vnext2-plan D25 / §9）**：`curl -fsSL https://raw.githubusercontent.com/Wan-ZL/zelin-ai-assistant/main/scripts/bootstrap.sh | bash`——preflight（macOS / Xcode CLT 经 `xcode-select -p`、永不自己弹安装对话框 / git / python3；claude 缺席只 warn）→ checkout 目录（默认 `~/Projects/zelin-ai-assistant`；`$HOME` 之外打出 §55 per-binary TCC 警告）→ clone 或 `fetch` + `--ff-only` 更新（本地改动 = 不动代码只装现状；非 git 非空目录 / 别的 repo 的 checkout = 拒绝，一个字节不碰）→ `config.yaml` 缺则从模板复制、存在永不覆盖 → `bash install.sh --non-interactive` → `python3 -m act.doctor --fresh-install` → `open` 看板。**同一条命令既是安装也是更新**；退出码 = install.sh 失败步数，再 = doctor 的 broken 行数——TCC 授权与凭证永不计入。`curl | bash` 的 stdin 纪律：整个脚本包在 `main()` 里、每个子进程 `</dev/null`。
- **`install.sh --no-launchd`（§23 追记）**：可与任何模式叠加；不装 launchd agent、不写 crontab（`launchd=skipped:--no-launchd…` / `cron=skipped:…`），改跑一次 `python3 -m act.actd --once` 证明 daemon 在这台机器上能跑完一个 pass（新 step `actd_once`：ok / fail / skipped，`fail` 进 `failed_deploy_steps`）。flag 解析改为循环：未知 flag = 用法错误 exit 2（在任何副作用之前）；`--check` 之后的参数原样透传 doctor（`bash install.sh --check --fresh-install`）。真空环境（无 config / secrets / state / claude / node / PyYAML）是每种模式的合法输入；步 5/6 的正文抽成 `install_launchd_agents` / `retire_legacy_launchd_agents` / `install_cron_lines`；收尾横幅改成「剩下的是你的」清单并指向机器版。
