- **探索式 UI 巡检 `ui_scout`：一个驾驶员在真沙箱里用看板（CONTRACT §79，issue #449）**——既有的浏览器判例都是写死的，只走有人想到过要写下来的那条路；#446 那一类肉眼可见的 bug 全是 owner 自己撞出来的。现在多了另一半：一个驾驶员（离线剧本，或一个多模态模型）在一次性沙箱里像人一样点、打字、等、看屏幕，旁边站着七只确定性判官（渲染崩溃 / console 报错 / 列头计数与数据对不上 → error；报警面 / 单步预算 / 文字被裁 / 英文界面漏中文 → warn）。一句话跑：`cd web && npm run ui-scout`（默认离线驾驶员，不花钱、不出网、确定性）；换成模型驾驶只是换一个环境变量：`ZAI_UI_SCOUT_PILOT='python3 ../scripts/qa/ui_scout_pilot.py'`。驾驶协议（`web/e2e/ui_scout/core/protocol.ts`）是模型无关的一页 JSON：截图路径 + 元素表进、一行动作出，Claude / Kimi K3 / 任何多模态端点都能开——参考驾驶员把截图路径交给模型自己 `Read`，调用仍然只经 `act/llm.py` 那唯一的 LLM 边界，本仓不为此新增任何运行时依赖。驾驶员只能按跑者发出的 `ref` 指认元素（写不出 selector），它吐出来的每一个字段都过消毒，它自己说的「这里不对」永远只记 info——线索不是判决。报告落 `.ui-scout/reports/<时间戳>/`（出生即 gitignore、只留最近 N 次）：`report.json` 给机器、自包含的 `report.html` 给人，每步一张截图 + 复现步骤；`python3 scripts/qa/ui_scout.py --issue-plan` 拿指纹比对已开的 issue，命中就让你去补评论而不是再开一条。
