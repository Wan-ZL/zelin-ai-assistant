- **隔离工作树（worktree）不再只增不减（issue #315）**：派出去的每个后台会话都会在 `.claude/worktrees/` 里留下一份完整源码副本（跑过前端的还带 `node_modules`），而在此之前**没有任何一处代码删过它们**——owner 的机器从 7 月攒到 190 多个，磁盘只涨、`git status` 越来越慢、本地分支列表里全是死枝。自本版起有三个回收点：卡结算的那一刻（owner 在 GitHub 上合并或关闭了它的 PR）顺手删掉这张卡自己的目录与本地分支；每日整理多跑一段，把「分支已在 origin 合并 / 已删枝」或「14 天没动过」的清掉；设置 → 开发者区多一行「隔离工作树（worktree）」，显示条数与占用，给一颗「清理」按钮。**安全边界写死在法条里**：有未提交改动的、锁定的、还有正在跑的卡指着的，一条都不删；删除只用 `git worktree remove`（永不 `--force`）与 `git branch -d`（永不 `-D`）。**提交一条都不会丢**：分支上有还没推上去的提交时，那条分支永远留着（目录满 14 天照清——目录是可再生的，`git worktree add <路径> <分支>` 一句话就长回来，提交不是）。`git worktree prune` 只在「会被它注销的登记全都落在这个目录之内」时才跑，免得一次误伤挂在别处的手工工作树。想先看看会删谁：`python3 -m act.lib.worktrees --dry-run`（一个字节都不动）。
