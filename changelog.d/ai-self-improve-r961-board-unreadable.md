type: fixed
- **`GET /api/board` 不再把「读不了这个文件」说成「这个文件不在」**（issue #423，CONTRACT §49 追记）：`server/board_source.board_bytes` 此前一个光秃秃的 `except OSError` 把每一种读失败都折成 404「dashboard.json not found — is actd … pointed at this AIASSISTANT_HOME?」，于是 live 机器上一个 425 KB 的好文件在 2026-09-17 16:44:32 起被那句话连答了约 1 小时 40 分，而真 errno 被这个映射藏了好几周、在任何面上都看不见。现在按 errno 分两路：`ENOENT`/`ENOTDIR`/`EISDIR`（真缺席、`state/` 被写成普通文件、`dashboard.json` 是个目录）仍是 404，文案与首次安装的空态一字不改；其余（`EACCES`/`EPERM`/`EIO`…）是新的 503 `BOARD_UNREADABLE`，`details` 带 `path` + `errno` + `strerror`。判据是 errno 不是异常类——`NotADirectoryError` / `IsADirectoryError` 直接继承 `OSError`，按类分流会把「HOME 指错」错判成「读不了」。
- **看板页据此多出第四态，并且不再对着一台在跑的 server 说「连不上」**（CONTRACT §54.1 追记）：503 `BOARD_UNREADABLE` 落进 store 的 add-only 字段 `boardUnreadable` 而不是 `boardError`——后者是四条健康 / 诊断横幅的共同闭麦开关，让它置位等于在唯一该说话的时刻全体噤声。旧快照留着，页面一行说清「读不到 dashboard.json …（errno N …）」+「重试」，**不给「立即生成一次」**：我们不知道那个文件里有什么，重建可能覆盖掉一份好数据。离线 / 缺文件 / 解不出来 / 读不了四态互斥；SSE 正在重连也不再压过这句实话（owner 的修法 `launchctl kickstart` 恰好会同时掐断 SSE 流）。措辞上一律不写「文件在」——errno 能证的只是「失败的不是『没有这个文件』」。
- **`GET /api/health` 说得出「我读不了那个文件」**（CONTRACT §47.4 追记）：新增 add-only 顶层键 `unreadable`（`{<块名>: {errno, strerror}}`，恒在，干净时 `{}`），`heartbeat` / `dashboard` / `loop_health` 三个读者各自的读失败都落进去，`stat()` 与 `read` 两种拒绝分别留痕。verdict 阶梯、`dashboard` 的 null 语义与「永不 500」都一字未改——`verdict` 断言的是管线活性，actd 跳得好好的时候那句 `ok` 本身是实话，缺的只是「有个文件我读不了」。反过来，一个**从读不到的文件推出来的** verdict 不许再被断言：`verdict: "stale"`（依据 = 「没有心跳文件」）撞上 `unreadable.heartbeat`（= 「心跳文件读不了」）时健康横幅整条闭嘴，不再一边说「后台服务没在运行」一边递上「启动后台服务」。
- **errno 进 `server.launchd.log`，不另开日志通道**（CONTRACT §54.2 追记）：访问行的 `(path, 状态码)` 采样器本来就让同一个错误每 300 s 报一行，它只是载不动 errno；现在 `_send_api_error` 把 envelope 里 `errno`/`strerror` 挂到同一行尾巴上，于是白拿那套分桶与窗口——`"GET /api/board HTTP/1.1" 503 - errno=1 Operation not permitted (+28 suppressed in the last 300s)`。一个写者、一份日志、一个抑制器。
