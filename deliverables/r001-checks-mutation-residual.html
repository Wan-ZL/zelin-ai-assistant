两个残差的判决

int_plus1@556:30#0 — 可证等价，永不可杀

raw.split("#", 1)[0] 的 maxsplit 1→2。str.split(sep, k)[i] 对任何 i < k 都与 k 无关：左到右切，第 i 段是真的第 i 段，只有第 k 段（余段）随 k 变——而这里 [0] 只读第一段。

353,982 条输入（长度 ≤6 的分隔符全排列穷举 + 随机含全码位 + 真 .gitignore 72 行）零差异。阳性对照：同一行的 int_minus1@556:30#0（1→0，真的会让注释不再被剥）在 200,533 条输入上报差异，且被两份判例都杀掉——说明这一行本身是被钉住的，存活的不是覆盖漏洞。

⚠️ 方向性：只有「增大」等价，「减小」是真变异体。任何抑制规则都不能一刀切。

return_none@572:12#0 — 判等价，故意不杀

_drift_scanner 内嵌闭包 dangling 的 return False → return None。两个值都是假值，唯一消费点是布尔位置，经任何公共入口不可观测。

它技术上可以用 fn.__closure__ 翻出来断言，但那样钉住的是「dangling 是个嵌套函数」这一实现结构——把它提成模块级函数或内联掉，行为一字不变而判例会红。这种判例比没有判例更坏（防腐 #7 的反面）。#391 独立地作了同一判断。

return_none@438:8#0 — 杀掉了，但明说它是类型契约

_unpinned 豁免分支返 False 还是 None，经 check_actions_sha_pin 观测不到（同样两个假值、同样布尔位置）。钉它的理由是同一函数另一条出口 not _SHA_RE.match(ref) 返真布尔——两条出口类型不一致，今天无害，这个值一旦进 details / JSON 就立刻可观测。

判例 docstring 里明写这是类型契约而不是行为锚定，没有把它算进「行为防护」那一档。#391 独立地作了同一选择并同样标成「选定不变量」。

与 @572 的区别不是随意的：_unpinned 是模块级私名、有隐式接口可以钉；dangling 只活在 closure cell 里，根本没有接口。

方法与可复现

复核器按 site_id 逐个施加变异、只跑定向子集、每个变异体独立 workspace、-f failfast（对退出码中性）。判决语义逐字照抄 scripts/qa/mutate.py::_execute_mutant（pass→survived / fail→killed / timeout→timeout）。每体约 0.3–0.5 s，12 并发跑满 839 个位点 1–2.5 min——比整轮 mutate.py 快两个数量级。

两条口径修正，给下一个 session

  • _module_score（mutate.py:739-745）把 timeout 记在分子（killed 侧）。所以子集变慢只会让杀伤率虚高，不会虚低——每往靶区加一份判例就多一分这个风险。
