TL;DR

设置页新增「录制数据与磁盘 / Recording data & disk」区（紧跟录制区）：当前占用（总 + 数据库 / 备份 / 日志 / 媒体 + 数据库内可复用空间）、每月增长估算（附依据）、最早 / 最新数据、上次清理回执、备份文件告示、刷新。数据来自新的只读端点 GET /api/screenpipe/disk，扫目录与只读问 sqlite 都在 server 后台线程，设置页渲染路径零磁盘 IO。

新旋钮录制数据保留天数（recording.retention_days / override screenpipe_retention_days），默认 0 = 永久保留 = 现状不变。设了 N ≥ 1，30 分钟 cron 链的 ingest/screenpipe-cleanup.sh 会调 act/lib/screenpipe_retention.py，只删「早于 N 天 且 已导出进 vault」的 OCR / 音频转写行，分批、带时间预算、不 VACUUM，回执落 state/screenpipe_retention.json，任何失败只进回执、链不断。

做了什么

1. 度量：server/screenpipe_disk.py + GET /api/screenpipe/disk

  • 缓存 TTL 600 s；首次 state: "computing"，后台算完 ready，后台失败 error 并释放 in-flight；?refresh=1 只在没在算时再起一个。
  • 扫描按类归并 db / backup / log / media / other，不跟符号链接；db.sqlite 只读 URI 问 page_size × freelist_count（= 清理后可复用字节）与首末 frame 时间戳，锁住 / 坏库进 db_error。
  • 增长估算：样本文件 state/screenpipe_disk_samples.json（间隔 ≥ 6 h、帽 240 条），最近 30 天首末样本跨度 ≥ 1 天给斜率（basis: samples）；不够退到 db 字节 ÷ 录制天数（basis: lifetime）；都没有 → null，界面说「样本不足」。

2. 保留期：act/lib/screenpipe_retention.py（stdlib sqlite3）

  • 删 frames（连带 ocr_text、elements）与 audio_transcriptions 里 timestamp < now − N 天 ∧ id ≤ export_markers/last_*_id 的行；未导出的一行不碰，标记缺席一行不删。
  • 每笔 2000 条、busy_timeout 30 s、单轮预算 120 s（用尽即停，回执 budget_exhausted，下一轮接着）；不 VACUUM。
  • CLI：python3 -m act.lib.screenpipe_retention [--dry-run] [--days N] [--db PATH]，stdout 一行 JSON；永不抛。
  • 挂点：ingest/screenpipe-cleanup.sh（cron 链第二步）多跑这一条；crontab 行本体（install.sh）未动。

3. 设置面：web/src/components/settings/StorageStatus.tsx + 目录 storage 区

  • SettingsPage.SETTINGS_TOC 新条目 storage（默认折叠，与其它非常用区一致）；fold 内 = CatalogSection sectionId="storage"，lead 槽渲 StorageStatus。
  • computing / refreshing 期间每 1.5 s 轮询、上限 40 次；拉取失败只显示一句 alert；备份文件告示 role=status。
  • 保留天数字段文案 server-owned（help 写明「已导出进笔记库」「不 VACUUM：文件不立刻缩小」「原始 jpg / mp4 一小时后照旧删」）。

CONTRACT 必答三问

  1. 触及哪些 §：新增 §71（71.1 度量端点 / 71.2 保留期与清理 / 71.3 设置面）；§18 追记（cleanup 步多一件事）；§68.1 通用目录新增 storage 区（复用 diff-write）；§49 新只读路由。
  2. §0 宪法：第 2 条「绝无不可恢复的自动删除」——默认关；开了只删导出标记之前的行，它们的文本已在 vault 2 - raw，那份笔记就是回程票 → 不修宪（§71.2 写明）。第 3 条：computing / error / db_error 如实报、估算依据随数字投影。第 7 条：stdlib only。第 9 条：只读 localhost、零上传。第 11 条：模块异常进回执 + || true，后台线程失败落 state: error。
  3. 既有机制：settings catalog（int 校验 / diff-write / server-owned 文案）、doctor_run 的 TTL 缓存形状、export_markers（已导出边界）、screenpipe-cleanup.sh（挂点）。未动受保护路径。

真机怎么验

  1. 合并部署后打开设置 → 「录制数据与磁盘」区：几秒内应从「统计中…」变成「43 GB」量级的数字，并列出 db.sqlite.bak-20260604（33 GB）。
  2. 先 dry-run 看会删多少：
cd /Users/zelin/Projects/zelin-ai-assistant && python3 -m act.lib.screenpipe_retention --dry-run --days 90
  1. 满意再在设置页把「录制数据保留天数」填 90（或别的数）并保存；下一轮 30 分钟 cron 之后，「上次清理」一行会显示删了多少帧 / 条转写；文件大小不会立刻缩，「可复用空间」会涨。
  2. 回执原文：cat state/screenpipe_retention.json。

边界与后续

  • 本机 launchd 的 a11y 日清 ~/.local/bin/screenpipe-prune-a11y.sh 不在 repo，本 PR 不动它（CONTRACT §55 提到的 plist 照旧）。
  • 不 VACUUM：要真正缩小文件需停引擎后手跑 sqlite3 ~/.screenpipe/db.sqlite 'VACUUM;'。
  • 增长斜率首日不可用（只有全程平均），第二天起有 ≥ 1 天跨度的两次采样后自动切换。
  • storage 区默认折叠；若希望首屏可见，改 web/src/settingsFolds.ts 的默认展开集即可（本 PR 未动，折叠集判例会随之调整）。
