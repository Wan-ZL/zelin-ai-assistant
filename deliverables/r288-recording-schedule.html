设计：门在冻结引擎外面

为什么不改 Recording.swift

它是 mac/ 冻结规范的逐字节副本（D3 + §61.3，tests/test_shell_engine_mirror.py 执法）。日程只借它三样公开的东西——mode、applyMode()（stop → start）、pgrep / pkill——全部经缝注入，harness 绝不真 pkill。

⭐ 唯一的取舍：3 拍宽限（≈10–15 s 残余帧）

冻结引擎的 applyMode 在 spawn 后 0.5 s + 7.5 s 里还在「慢死亡观察」；那时被 pkill 会被它读成「新模式没起来」并回滚到上一个模式、弹「已退回…」——那是日程造成的假回滚。所以暂停期间若引擎被别的路径拉起（TCC 自愈、owner 在窗外点了模式 / 重启），要连续 3 拍看见它在跑才停。边界跨越、醒来、刚开日程那一拍不受此限，立刻停。代价写进了 §61.7。

快照与方法（§61.1 add-only）

recording.schedule = {"enabled": false, "start": "09:00", "end": "19:00", "days": [2,3,4,5,6], "paused": false}
// paused ⇒ recording.diagnosis = null, recording.log_tail = ""   （故意停不是故障）

setRecordingSchedule {enabled?: bool, start?: "HH:MM", end?: "HH:MM", days?: [int 1…7]}
// 全部可选、至少一键；合并后整份校验（含 start ≠ end）；任一坏值 → INVALID_ARGS，零写入、零执法

偏好键（壳 UserDefaults，与 recordingMode 同域）：recordingScheduleEnabled / recordingScheduleStart / recordingScheduleEnd / recordingScheduleDays。坏值逐键回落默认；start == end 回落默认窗口；坏日程恒「在窗内」（宁多录，绝不停死）。

面：三个非录制态必须可区分

状态词颜色含义
mode off关 / Off次级文字色owner 没开录制
开着没录上未在录制 / Not recording橙（警告）故障：权限 / ffmpeg / Node / 崩了（死因照 §61.2）
日程窗外按日程暂停 / Paused by scheduleaccent（is-sched）故意停着，到点自动恢复；菜单说日程本身；「重启」禁用

落点

  • 顶栏 RecordingControl：第三态词 + 菜单说明行「按日程暂停中——只在 09:00–19:00 · 周一至周五 录制，到点自动恢复」；三态单选照常可点（改 mode，日程不动）。
  • 设置 → 录制 RecordingScheduleBlock：开关 / 星期即改即发，时刻失焦或回车才发，每次只发改动的键；至少留一天（页面先拦）；桥 reject 原文照印 + 时刻回滚；老壳（UNKNOWN_METHOD）退成说明句。
  • 录制与数据接入页：状态词 + 日程句，权限 / 死因分支不出（壳已把 diagnosis 置 null）。
  • 权限体检 consent 行 / 向导终章：暂停 = 中性行，不算失败。向导没加日程步（issue 标 optional；默认关的功能不该在首次运行多问一步）。
