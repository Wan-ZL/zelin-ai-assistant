**调查（只读 live 机器）**：`auto-deploy.log` 逐行显示 `refresh_stable_claude` 没有错——2.1.261 在 09-05T04:43Z 装上、06:59:57Z 的第一次部署就 `refreshed`；2.1.263 在 09-06T03:05Z 装上、09-07T04:38:55Z 的第一次部署就 `refreshed`。中间那段落后是 §55 第五幕「`up_to_date` 轮不跑 install.sh」的设计内滞后，doctor 的 WARN 当时说的是实话。真正的洞：这段窗口里终端的裸 `claude`（新）与 worker（副本，旧）是两个版本，而看板给 owner 的命令就是裸 `claude`。顺带看到的第二件事：Claude Code ≥ 2.1.26x 有 per-user daemon（`claude daemon run … --spawned-by {"label":"claude agents"}`，ppid 1，活过了所有 actd 重启），`--bg` worker 是 daemon 预起的 spare、跑 daemon 自己的 binary（ps 里 `-- ~/.local/share/claude/versions/2.1.263 --bg-spare`）；daemon 由它消失后第一个 `claude` 命令起，live 上正是 actd 投影 pass 里最后一处裸 `["claude", "agents", "--json", "--all"]`（登录 shell 的新版），同一个 actd 却用旧版副本派发。

**改了什么**：(1) `act/lib/dashboard._takeover_claude(cfg)` = `config.resolve_claude_bin(cfg)`（与 `llm.dispatch_argv` 同一解析）经 `shlex.quote` 成一个 shell 词，`copy_cmd` 三种形（`attach` / `--resume` / `cd … && --resume`）一律以它开头，路径不是本机可执行文件时才退回裸 `claude`；每次 build 解析一次挂在 `_Ctx.claude_word`。wire key 不变，server §68.7 逐字推导、零改动继承（PR #246 所有的文件一个没碰）。(2) 同文件 `_claude_agents_stdout(cfg)` 走同一解析——act/ + server/ 自此零裸 `claude` argv（判例扫描）。(3) install.sh `refresh_stable_claude` 在 `cmp` 之后、`codesign` 之前问新函数 `stable_claude_in_use`（`lsof -t -w -- <副本>`），有进程在执行副本就推迟：副本保留、`info` 一行、`stable_claude=skipped:in use by N process(es) …`，永不 fail；没 lsof = 0（fail-open，即今天的行为）。(4) doctor `stable claude` 的版本差 WARN（`claude_bin._version_gap_row` + `live_users`）：detail 点明两边都跑副本、别手敲裸 `claude --resume`；fix 按 lsof 二选一——N 个进程在跑 → 等它们结束 / 在看板上停止后 `bash install.sh`；0 → 现在就 `bash install.sh`。
