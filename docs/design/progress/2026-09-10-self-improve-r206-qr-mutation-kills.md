**做了什么**：夜报把 `act/lib/qr.py` 列成存活最多的模块（当晚预算内跑了 183 个位点，81 杀 102 活）。本地全量跑该模块 1,198 个位点：**455 存活，杀伤 62.0%**。逐个判读后，存活体的分布只有一个故事——**测试只编了六七个 payload，于是三张静态表里没被走到的格子随便改一位都没人红**：357 个存活体（78%）落在 `_EC_TABLE`（每个 version × EC 级别的块布局）和 `_ALIGN_POS`（对齐图案中心）里，剩下的落在 PNG 容器、罚分规则的非对称边、掩码选择的取舍上。

补的判例按「结构不变量 + 真解码」两条腿，不靠再多编几个 payload：`tests/test_qr_tables.py` 把 ISO/IEC 18004 的结构不变量写成判例（每个 (version, ec) 的块布局必须**正好用满**该 version 的数据模块总数——模块数由独立公式算出；group-2 的块恰好多一个数据码字；纠错越强容量越小；对齐中心的个数与坐标由 version 唯一决定；GF(256) 的 exp/log 互逆、指数表 255 周期；40 个 (version, EC) 的 byte-mode 容量边界直接照 ISO 表 7 钉死，+1 必须跳版本），R-206 侧穷举验证过：三张表里**任何一格 ±1 都至少撞破其中一条**。`tests/test_qr_version_sweep.py` 在这 40 个容量边界上各编一张码，再用新的 `tests/qr_testkit.py`（判例侧独立解码器：读格式信息 → 反掩码 → 之字形回读 → 反交错 → Reed–Solomon 校验子 → 载荷逐字节回读）解回来对拍——扫描枪读什么，判例就读什么，整轮 1.6 秒。`tests/test_qr_png_bytes.py` 把 PNG 真的解开（逐 chunk 校验 CRC、IHDR 字段、zlib 解 IDAT、逐行确认滤波字节为 0、按 scale/quiet 还原模块矩阵）——原来只看头 8 个魔术字节，安静区宽度 / 缩放偏移 / 黑白像素值 / 位深全是免检区。`tests/test_qr_mask_selection.py` 逐 payload 钉住**被选中的掩码号**（八个掩码各有一个代表 payload，外加一个两号掩码罚分打平的 payload 钉「取小号」）——`range(8) → range(7)` 与 `p < best[0] → <=` 从此活不下来。`tests/test_qr_penalty_and_masks.py` 补非对称素材：原来的规则判例只用全黑 / 棋盘 / 尾部 run，rule 2 的邻居下标、rule 3 的 ×40 权重、rule 4 的百分比分桶、四条规则的加总方向全都测不到。`tests/test_qr.py` 里那段手抄的解码器换成 testkit（行为不变，去重）。

**结果**：同一轮重跑 1,198 个位点，**存活 455 → 43，杀伤 62.0% → 96.4%**（`scripts/qa/mutate.py --modules act/lib/qr.py --force`）。零生产代码改动——这轮没在 qr.py 里挖出真 bug，三张表与 ISO 逐格相符（40 个容量数与 ISO 表 7 的公布值一致，这是外部真源交叉验证，不是自证）。

**剩下的 43 个是等价变异体，逐个用机器复核过**，不是「看着像」：把每个存活体真施加到模块上，与原模块在一大片可观测面上对拍（40 个 version×EC 的成品矩阵、8 个 payload × 4 个 EC 级别的矩阵与终端渲染、`_choose_version` / `_data_bits` / `_pad_codewords` / `_gf_mul` / `_rs_ec` / 四条罚分规则 / 八个掩码条件的逐点输出、三组 scale·quiet 的 PNG 解码像素）——**40 个逐字节完全相同**，1 个（`zlib.compress(..., 9)` → 8）只改压缩后的字节、解出来的图像一模一样，2 个（`draw_function_patterns` 里 `self._draw_format(0)` 这个**占位**调用的实参 ±1）只改一个随后必被真格式信息覆盖的中间态。分类：① 对称区间上的 `+ → -`（`range(-4, 5)` / `range(-2, 3)` 里的 `x + dx`，集合不变）；② 奇偶等价（四个掩码公式里的 `+ → -`——模 2 下同）；③ 预留区随后被覆盖（finder 多扫一圈、格式信息循环多走一位、占位实参）；④ 循环上界的余量（`while col > 0` 越界那一步码字流早已耗尽；`range(len(line) - 10)` 多/少一个窗口，短切片永远匹配不上 11 元图案）；⑤ 常数被下游整除吸收（byte mode 下 `need_bits ≡ 4 (mod 8)`，`4 ± 1` 与 `+7 → +6/+8` 的向上取整结果不变；终止符位数与对齐补零都只写 0，总长恒为 `L + 4`）；⑥ 分桶算术里同桶内的 ±1（`//5*10` 吃掉）；⑦ 永不被读的哨兵与占位（`1 << 60`、`_GF_EXP` 的填充值、`x <<= 1` 后恒为偶数所以 `& 0x100` 与 `& 0x101` 同真、`if coef != 0` 与 `range(1, len(gen))` 是纯优化守卫）。这些不该再补判例——为它们写测试等于把实现细节钉死，反而挡住以后的重构。
