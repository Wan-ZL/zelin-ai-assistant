law: §70.7 追记（两类信号 / `last_result.advisories` / `skipped.advisory` / 默认额度 2）；§2 `maintenance` 形状 add-only 扩一键；§15 追记的 override 层次不变

**为什么**：循环上线（09-02）后头一周铸了 15 张 🤖 卡，其中 9 张是同一根因的症状——launchd 起的 claude 没有完全磁盘访问（D20 → D26 → D27 那条线）：派发卡死一张、doctor `launchd claude` 红灯一张、launchd 日志 `tcc_eperm` 一张、actd.log 刷屏一张、事件风暴一张……每天各来一次。它们全部是真信号，但没有一张能派给 agent 做：修法是 owner 在系统设置里点一次授权。循环按 §70.3 的读取器设计只会问「这个形状出现了吗」，不会问「这个形状是代码能修的吗」——D27 已经给 doctor 行分了 `row_class=owner_action`，循环却没有用上它。owner 拍板两件事：默认额度 5 → 2；自检类信号改成只进 digest / 横幅、不铸可派发的卡（至少 owner_action 的一律不铸）。

**做了什么**：`act/lib/loop_inputs.py` 两个模块级元组——`CARD_KINDS`（issue / pr_red / pr_comment / mutation / material：GitHub 面 + owner 亲手放的素材，照旧铸卡）与 `ADVISORY_KINDS`（stuck_dispatch / unclassified_failure / event_anomaly / radar_give_up / write_storm / log_loop / install_step_fail / launchd_fault / doctor_fail：只转成 §70.3 ⑩ 已有的非卡对象 `Summary`，新增 add-only 字段 `fingerprint`）；`is_advisory(sig)` = kind 在 ADVISORY_KINDS **或** `failures.row_class(sig.ref) == owner_action`（belt and braces：日后有人把 doctor_fail 搬回可铸卡，owner_action 的行也铸不出来）。`daily_loop.collect_signals` 末尾 `split_advisories` 分流（按原 priority 排），`select_signals` 再守一道（审计 `skipped.advisory`，正常恒 0）。持久化：`last_result.advisories`（≤ 20 条 `{kind, text, ref, fingerprint, first_seen}`，`first_seen` 从上一轮同指纹的行继承——「launchd claude 从 09-01 就红着」比「今天红」有用）+ 审计行同名键；投影 `maintenance.last_result.advisories` 逐字带过（每字段 str，坏形状整行丢）。web `MaintenanceBanner`：advisories 非空时同一行右侧多一个「系统自检 N 条」按钮（`aria-expanded`），点开在横幅下方列 kind / text / 首见日期；三计数全零而 advisories 非空也渲染；仍不弹系统通知（D10）。默认额度 `config.DEFAULT_DAILY_LOOP_MAX_PROPOSALS = 2`（server/settings.py 手抄同值，镜像判例钉住；config.example.yaml / 设置页 hint 同步）；已有 override 的机器不受影响。

**没做的**：读取器与阈值一字不动——advisory 只是「不铸卡」，不是「不读」；`inputs.<reader>` 仍数两类信号，看得见每个读取器活着。D18 的非 owner issue 摘要行仍只活在审计行与 `last_result.summaries` 计数里，不进横幅（不在 D33 范围）。没有新 inbox 动词、没有通知。

**判例**：`tests/test_daily_loop_proposals.py::AdvisoryKindsTestCase`（按 ADVISORY_KINDS 参数化：selector 不选 / collector 转 Summary；正则钉住 loop_inputs 每个 `Signal(kind=…)` 构造点都归两类之一；owner_action 不论 kind；first_seen 继承 + 20 条帽），`tests/test_daily_loop_run.py`（doctor 红灯成 advisory 不成卡、owner issue 照旧成卡、first_seen 跨天、投影逐字），`tests/test_server_settings_daily_loop.py` 默认值 2，`MaintenanceBanner.test.tsx` 三条新判例。视觉 golden 不受影响（demo seed 没有 `maintenance` 键）。
