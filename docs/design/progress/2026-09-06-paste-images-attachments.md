**做了什么**：审计确认（gap `composer-paste-images`，impact high）原生 PastedImages.swift 的整套贴图在 web 只差一条落盘通道——server 的 inbox_writer 与 actd 早就接受 `images[]` 路径，`GET /api/board` 之外本面却「零上传」，web 页面又没有文件系统。D41 按 owner 的整体授权代拍选项 (a)：补上传面，不动 wire。**server**：新模块 `server/attachments.py` + 路由 `POST /api/attachments`（`app.py` 新增二进制体路由表 `_POST_RAW_ROUTES`：path → (media type, 上限, handler)；`_check_write_auth` 的 Content-Type 闸自此按路径取 media type——本路由 image/png、其余仍 application/json，`security.content_type_is(ct, media_type)` 是 `content_type_is_json` 的泛化；`_content_length(raw, limit)` 多一个上限参数，JSON 面的 1MiB 一字未动）：body = 原始 PNG 字节，验 8 字节签名，server 铸 `<uuid4>-1.png` 落 `state/attachments/`（`paths.attachments_dir`，与 actd GC 同一处），0600 + O_EXCL|O_NOFOLLOW 写 `.tmp` 再 replace，回 `{ok, path, bytes}`；没有读回、没有 DELETE。放宽 Content-Type 闸的安全论证写进 `security.content_type_is` docstring：只许登记非 CORS-safelisted 类型，image/png 跨源必预检、本面对 OPTIONS 不答 CORS 头，present-only Origin 判定的兜底不失。**web**：`api.postAttachment(png)`；纯逻辑 `components/board/pastedImages.ts`（剪贴板图片 flavor 提取、§29ter 认领真值表、canvas 降采样到 2560px 转 PNG、超 server 上限减半再编、4 / 2560 / 8 MiB 常量与 server / 原生同值）；`LaneComposer.tsx` 加 onPaste 认领（位图 + 实质文本让路并亮 3 s 提示）、📎 文件选择器、缩略图行（≤4，✕「移除这张图」，本地 blob URL 预览）、贴入即上传、提交时 `images:[路径]`（无图不带键，golden 字节形不变）、上传在途禁点提交、失败弹原生同名「图片保存失败」+「好」且草稿与其余图保留、附图与文字草稿同命（Esc / 被拒 / 斜杠命令不丢，成功才清）。`FeedbackDialog` 保持文字-only（注释改为明文决策）。**§66**：`parity.test.tsx` 的「server 拒绝」遍先往第一个输入框粘一张截图、上传被拒、收弹窗、点「好」；pending.txt 划掉 `control:board.dialogs:label:images-could-not-be-saved` / `control:board.dialogs:alert-button:ok`（PRESENT 830 → 832，PENDING 13 → 11，report.json 随之）。

**几处与原生不同、按实际行为说话的取舍**：(1) 上传时机 = 贴入而非发送——浏览器没有本地文件系统，失败必须当场可见、可重试；代价是丢弃草稿留孤儿 PNG，交给既有的 30 天 GC；(2) 失败弹窗正文不说原生的「已只提交文字部分」（那一刻什么都没发），说「这张图没有加进附图；文字与已加的图原样保留」；(3) ⌥⌘V 强制贴图不搬（浏览器 / WKWebView 没有可靠的 `navigator.clipboard.read()`），📎 从「读剪贴板」改为「选文件」；浏览器自带的 ⇧⌘V「纯文本粘贴」天然是 ⇧⌘V 强制文本的对应物；(4) Finder 拷贝的图片文件在浏览器里的文本 flavor 是文件名——认领规则多认「文本恰为其中一个文件的名字」，否则 Finder 拷来的截图永远贴不进来。
