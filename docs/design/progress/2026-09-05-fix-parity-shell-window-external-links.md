**审计发现壳窗口这一层丢了四条原生行为**，全是 `shell/Sources/main.swift` 一处的疏漏、彼此独立：(a) `AppDelegate` 只做 `WKNavigationDelegate`，没有 `WKUIDelegate`——WebKit 的合同是「不实现 `createWebViewWith` 就取消该导航」，web 面 16 处 `target="_blank"` / `window.open` 在壳里全成空操作（原生 `DepAction.url` / `FailureCatalog.perform` / `openReleasePage` 都是 `NSWorkspace.shared.open`）；(b) `applicationShouldHandleReopen` 按 `hasVisibleWindows` 判——字幕悬浮 `NSPanel`（`orderFrontRegardless`）在场时它恒为 true，Dock 点击成空操作，而原生 `AppDelegate.swift:195-207` 早就为同一件事改成了「只看看板窗口」并把理由写进注释；(c) `contentMinSize` 900×600 比原生（720×480，为分屏放宽）和 web 自己的布局 token 都严；(d) `window.title` 只在建窗时设一次，原生 `installTitleSink` 是随 section / 语言重算的。另有 splash 与两个失败弹窗只有单语。

**修法**：三条判断抽成 `ShellSupport.swift` 里的纯函数——`ExternalLinkPolicy.classify(url, port)`（board / external / ignore；origin 三要素 scheme + 回环主机 + 端口全对才是 board，同主机其他端口是别的本地服务）、`ReopenPolicy.shouldShow(boardVisible:, boardMiniaturized:)`、`WindowTitlePolicy.resolve(pageTitle:, fallback:)`；`main.swift` 只问策略做副作用：`uiDelegate = self` + `createWebViewWith`（分流后返回 nil，壳永远一个 webView）+ `decidePolicyFor`（主 frame 外跳 `.cancel` + 外开；子 frame / 新窗口请求放行）、Dock 重开读 `window.isVisible || isMiniaturized`、`contentMinSize` 720×480 注释指向 `ui/tokens/native-tokens.json`、KVO `webView.title` → `window.title`。splash / 两个 `NSAlert` 改 `L(zh, en)`，命令与路径逐字不译（这些句子出现在 server 连不上的时刻，server-owned 目录拿不到，`L()` 是壳既有机制、不是第二套 i18n）。

**判例**：新 `shell/tests/PolicyHarness.swift`（与 BridgeHarness 同法：每个非 main 源 + 本文件作 main 编成 CLI，33 格），`shell/tests/run.sh` 加第 [4]/[5] 步（compile_harness 抽成函数，BridgeHarness 一字不改——它归 `shell-recording-bridge`）。本机：typecheck 零新警告、`shell/build.sh` 通过、run.sh 全绿。刻意不启动壳 app 做手动验证：构建出的 bundle 与 owner 装机版同 bundle id，会读写同一份 UserDefaults 并可能自启录制引擎。web 半（每页 `document.title`）与 `buildMenu` l10n 分别属 `appshell-dashboard-missing` / `shell-menu-l10n`，本批不碰。
