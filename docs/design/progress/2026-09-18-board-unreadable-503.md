**病灶**：`server/board_source.board_bytes` 只有一个 `except OSError`，把**一切**读失败都映成 `NotFoundError`。owner 机器上（HOME 在外接 APFS 卷 `/Volumes/Storage`，server 由 launchd 托管跑 `/usr/bin/python3` 3.9）于是出现这样一天：13:44 起 `GET /api/board` 连答 3 小时 200，**16:44:32 翻成 404** 并持续（日志里每 300 s 一行 `+28 suppressed`），`launchctl kickstart -k` 能修，18:24:51 再翻。那个 425 KB 的 `state/dashboard.json` 一直在那里、`-rw-r--r-- zelin:staff`、同一个解释器在终端里读得动。**真正的 errno 一次都没落过盘**——客户端拿到的和「文件真的不存在」逐字节相同（本轮跑了一份复现脚本对照：两种情况的 status / code / message / details 四样全等，`/api/health` 也都是 `dashboard: null` + `verdict: stale`）。宪法第 3 条要求「坏掉的通道」与「没有新数据」严格区分，这条路上是破的；§54.2 2026-09-14 追记里那 **1549 行一模一样的 `/api/board 404`** 被整类当成噪音收编，噪音闸没错，被它压住的那条**假**消息才是病根。

**改法**（四个 server 文件 + 六个 web 文件，各自可单独回滚）：
1. **`board_bytes` 分类**：`FileNotFoundError`（ENOENT——叶子缺席 / 父目录缺席 / 悬空软链）→ 404 `NOT_FOUND`，**消息与 `details.path` 一字节未动**（§49 追记 2026-09-05 的判据、四份 web fixture 与 `scripts/qa/shell_ui_probe.py` 逐字引它）；其余 `OSError` → 新的 503 `BOARD_UNREADABLE`，`details = {path, errno, strerror}`。分界线必须是 `FileNotFoundError` vs `OSError` 而**不是** `PermissionError`——本机实测 EPERM(1) 与 EACCES(13) 都是 `PermissionError` 而 EIO(5) / ELOOP(62) / ENAMETOOLONG(63) 是裸 `OSError`，按 `PermissionError` 分会把 I/O 错误漏回 404。
2. **503 的消息刻意不断言文件存在**（`cannot read dashboard.json — see details.errno`）：实测 ENOTDIR(20，父目录是个普通文件) / ELOOP(62) / ENAMETOOLONG(63) 都落在 503 这一臂，而这三路谁也没查过那个文件在不在。写「在、但读不动」就是本 PR 要修的那类「没查就断言」的新版本（§47.4 追记 2026-09-05 punish 过同一件事）——真相只有 errno，所以全放 `details`。
3. **`/api/health` 加 add-only 键 `dashboard_error`**：读被拒 → `{path, errno, strerror}`，其余一切情况（读成功 / 缺席 / 正文不是 JSON / 正文不是 UTF-8 / 顶层不是对象）恒为 `null`。`dashboard: null` 的含义一字不变，verdict 词表仍是五枚。`_dashboard_view` 改收**已读好的 body**（读与分类收进 `snapshot()`），好让 `dashboard.json` 每次 `/api/health` 仍然只读一次（§47.4「它只 stat 三个文件」）。
4. **errno 落一份到日志**：`_send_api_error` 对 `details` 带 `errno` 的受控错误多写一行 `<CODE> errno=<n> <strerror> path=<…>`，经 `Handler.log_message`（§54.2 的唯一 stderr 写者，测试套件替换它就能静音）与一个**独立**的 `_PollSampler` 实例（同一个类、同一个 300 s 窗）。
5. **客户端四态**：503 从 5xx 桶里划出来，落 store add-only 字段 `boardUnreadable`；无快照 → AppShell 整页第四态，有快照 → ErrorBanner 第三个 warning 变体；向导终章「首次数据」行说实话并撤掉播种按钮；设置页诊断区多两个字段。

**取舍**（每条都是 review 打回来才定的）：
- **`dashboard_error` 取顶层新键，不加第六个 verdict、也不塞进 `dashboard` 块**。加 verdict 会**静默失效**：`PipelineBanner.describeHealth` 的 `default: return null` 让新 verdict 一个横幅都不渲染（比今天更差），`repairActd.isRecovered`（`verdict === "ok" || "unknown"`）还会把每次一键修复都报成 15 s 超时，而 `types.ts` 把 verdict 声明成 `| string`、tsc 一个都拦不住。塞进 `dashboard` 块要让 `_dashboard_view` 在读被拒时返非 null，那会翻转 `_verdict` 并把向导「首份数据」行从红翻成**绿色的谎话**。顶层键一条既有判例都不碰（全套 health 判例里没有一条按整份 body 比相等）。
- **`PipelineBanner` 刻意不长 `dashboard_error` 分支**。原方案要它长，被否：它和看板页的新面同源，两条 `role="alert"` 说同一句话正是 §47.4 读者 3 与 `ErrorBanner` 组件头注都明令禁止的「同一信息绝不双份」，而且插在 verdict switch 之前会盖掉 `stalled` / `failing` 这两条更急的真话。只改一处：`stale` 正文里 `dashboard == null` 此前一律说「看板从未生成」——读被拒时那是假话，改为「看板数据读不出来（errno N）」。
- **`isBoardUnreadableError` 不写成裸 `status === 503`**：本面另一枚 503 是 §68.7 的 `SHELL_UNAVAILABLE`，把「壳没在跑」说成「看板读不动」是同一类谎话。判据 = `503 ∧ (BOARD_UNREADABLE ∨ REQUEST_FAILED)`，后者覆盖 envelope 体自己都解不出来时 `api.request` 的退化码。
- **`boardUnreadable` 不清快照**（与 404 相反）：文件在，上一版看板仍是管线写过什么的真话（照 `boardDecodeError` 的韧性先例）。落 `boardError` 被否——它的读者全把它读成「离线」，等于对着一台刚答过话的 server 说连不上，还会把 PipelineBanner / DiagnosticsStrip / MaintenanceBanner / SelfImproveBanner 四条横幅一并关掉（§49 追记 2026-09-05 为同一理由否决过一次）。
- **新面绝不复用 `BoardMissingState`**：它给的「立即生成一次」会 `POST /api/setup/seed-dashboard` → `write_dashboard` 原子替换 `dashboard.json`，而 `registry.load_all` 对读不动的卡片文件是**静默跳过**——在一台只是读不动的机器上那是拿一份可能零卡的看板盖掉最后一份好快照，即数据丢失。向导那一行同理撤掉 fix。
- **`_board_dict` 不动，让 503 穿透到派生路由**（`/api/cards/{id}`、deliverables、ai-fix、terminal）：让它吞掉会使卡详情改口答「查无此卡」——同一类谎话的新版本。`POST /api/terminal` 自此有两种语义不同的 503，页面的复制降级判据读的是 code 而不是 status（`terminalTakeover.ts` 本来就这么写），降级面零改动。
- **`_read_json_or_denial` 的子句顺序是承重的**：`UnicodeDecodeError` 是 `ValueError` 而**不是** `OSError`，它必须与 `json.loads` 共用同一个 try。第一版把 `except ValueError` 只挂在 `json.loads` 上，一份非 UTF-8 的 `dashboard.json` 就会让 `snapshot()` 抛出去、`/api/health` 变成 500 + 一份栈——正好是本 PR 要消灭的那类事故。判例按真字节 `b'{"generated_at": "\xff\xfe"}'` 钉住。
- **诊断行的桶键含 errno，整段包 `try/except`**：同一个 code 共用一个窗会让 EACCES 之后的一条 EIO 被计进 suppressed，读日志的人把 I/O 错误诊断成权限问题——采样器的立论本来就是「变化是信号」。`_send_api_error` 是从 `_dispatch` 的 `except ApiError` **子句里**调的，从那里抛出去的异常同级 `except Exception` 兜不住，会逃到 `handle_one_request`，客户端连 envelope 都收不到；日志出 bug 绝不许赔上这次回答（判例直接注入一个会抛的 `_errno_diagnostic`）。

**边界 / 没做（诚实交代）**：
- **errno 的 OS 层根因不在本 PR**（issue 的第 3 项）。owner 侧那个只读诊断 job（`com.zelin.diag-read`）会在下次翻掉时记下 errno；本 PR 只保证那个数字到得了人眼前。
- **壳冷启动那一路仍说假话**：`shell/Sources/main.swift` 的探活只认 2xx（`(200...299).contains(code)`），503 与今天的 404 一样走 10 s 超时后的「连不上看板服务」启动失败页，上面三条修法全是 launchd 的。只有**窗口已经开着时**翻掉（issue 里 16:44 那一次）才走得到新面。§54.2 的后续，未开卡。
- **「为什么会被重定向到向导」没修**：`/api/setup` 的 `needed` 判定里 `secrets_store.read_value` 同样 `except OSError: return None`；而 `server/setup.py` 用的是 `Path.is_file()`，它**不**吞 EACCES——本机实测 mode-000 目录里的文件 `is_file()` 直接抛 `PermissionError(13)`，所以 stat 级拒绝下 `/api/setup` 自己就是 500 + 一份栈（open 级拒绝下 config 与 setup_done 反而读成「在」，`needed:true` 只经 secrets 那条吞咽路径出现）。这是同一病灶的兄弟，另开一张卡。
- **`health._age` 的 stat 拒绝没管**（心跳文件的 `os.stat` 也吞 OSError）：那是另一条读者、另一个键，不在 issue 范围。
- 不动 `_read_json`（心跳与 loop_health 共用它）、不动 `_verdict` 的三入参、不给 503 加 `Retry-After`（客户端只重试**抛错**的 fetch，503 不在其列）。

**判例**：新 `tests/test_server_board_read_denied.py`（21 条：ENOENT 三形 → 404 且消息 / details 逐字；EACCES / EPERM / EIO / EISDIR / ENOTDIR / ELOOP → 503 带 errno；errno 为 None 也不崩不回 404；503 消息不出现 exists / is there / 但文件在；真 chmod 000 的端到端 503 envelope + `/api/health` 同一个 errno 且仍 200 + 同一个 HOME 上删掉文件仍 404；诊断行首条写 / 同 errno 窗内压制并把条数挂到下一条 / **换 errno 立刻写** / `ZAI_LOG_POLLS=1` 关采样 / 无 errno 的受控错误一行不写 / 诊断出异常不吃掉 envelope / 两个采样器实例不共用桶）。`tests/test_server_health.py` 加 `DashboardErrorTestCase` 七条（好 / 缺席 / 撕裂 / 非 UTF-8 / 读被拒 / verdict 不长第六枚 / **每次 snapshot 只读一次**）。`tests/test_server_board.py` 加派生路由那一条。`tests/test_server_health_verdict_ladder.py` 两个 `_dashboard_view` 调用点随入参换形（钉的行为一字未变，另加「body 为 None → None」）。web 侧：新 `store.boardUnreadable.test.ts`（分类真值表含 `SHELL_UNAVAILABLE` 反例、快照不清、冷启动、zh 文案、四态互斥来回、404 清快照后 503 不复活）、新 `AppShell.boardUnreadable.test.tsx`（八条：整页态、**没有「立即生成一次」/「启动后台服务」**、重试走 refreshBoard、有快照走 warning 变体且不承诺自动重连、**恰好一条 alert**、zh、回收站同此一态、设置页不受影响）、新 `FinaleStep.dataReadDenied.test.tsx`（三条：行说 errno、撤掉播种按钮、真的没生成时老行为不变）、`PipelineBanner.test.tsx` 加四条（从未生成 vs 读不出来、stalled / failing 优先级不变、健康管线上读被拒不长横幅）。既有判例零改动。
