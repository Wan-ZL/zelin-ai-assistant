**审计确认的三条丢失行为**（gap ids：`settings-credential-failure-reason-classification` / `settings-credential-network-failure-state` / `settings-slack-verify-identity-note`）。原生 KeyProbe.Outcome 是三支——ok / unauthorized（凭证本身的错）/ failed（网络或服务，判决未知）——web 把后两支拍成了一支：`SecretRow.probe()` 对一切非 ok 都 `setVerified(false)`，章翻成「验证失败」，句子却写「网络不通（不是凭证的问题）」；server 侧 `_probe_anthropic` 把一切非 200 当凭证错（529 过载也算）、`_probe_slack` 把一切 auth.test 错误码当凭证错（`ratelimited` 也算）。分类人话（原生 humanAuthReason：Slack 重新生成 token、Gmail 三个 Workspace 管理员 telltale「此路不通」/「粘的是普通密码」/ 通用句、Anthropic 去 console）在 server / web / shell 里一处都没有，用户只看到 `IMAP LOGIN rejected: [AUTHENTICATIONFAILED] …` 这样的原文。Slack 验证通过后原生的「已验证 ✓ 已连接 <team>，身份 @<user> 自动填好——不用再改任何文件。」与随之的 `loadDirectory(refresh:true)` 也没搬：server 早就把 team / user 放进了 `extra`，web 只渲 `detail`。

**落点**：server `verify()` 在凭证错的回执上多带 add-only `reason {zh, en}`（`AUTH_REASONS`，server-owned 双语，web `pickText`——与上一批的 `XOXB_REFUSAL` 同一机制，不设第二套 i18n；raw = 既有 `detail` 原文一字不改，跟在括号里）；`ProbeNetworkError` 从「DNS / 超时 / 拒连」放宽到原生 `.failed` 的全部（Anthropic 非 401/403、Slack 非 token 形状错误码、非 JSON 回应）；ok 与 network 的回执形状零改动。web 三分渲染：凭证错 → 章「验证失败」+ reason；判决未知 → 章**不翻**（`verified` 回 null = 「已保存（未验证）」，原生 state 3/4 → 2）+ 橙色「无法验证（网络/服务问题），稍后点「验证」重试：」+ detail；Slack 探已保存的 token 成功且 team / user 都在 → 身份句 + store 计数 `slackTokenVerifications` +1 + 目录刷新，`SlackDirectoryPicker` 看到挂载后计数变化就 `fetchSlackDirectory(refresh=true)` 一次（挂载前的次数不算、正在加载则跳过 = 原生 guard）。粘贴即验证的 Slack 成功**不说**「自动填好」（server 那条路不落盘也不回填）。`SlackSection.tsx` 未动（归 `catalog-help-copy` 批）。
