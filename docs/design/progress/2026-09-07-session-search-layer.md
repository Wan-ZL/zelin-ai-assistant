**spec 留白处的取舍**：(1) 「size-capped」做成**读门**（文件超 32 MiB 不读、`truncated: true`）+ 每条 `TEXT_CAP` 尾裁，而不是按字节裁响应：读门是真正的内存 / 响应上限（响应 ≤ 文件 ≤ 读门），per-entry 裁是对手编 / 旧版文件的防御，两者都诚实可见（`truncated`）。(2) 文件不在与坏 JSON 都回 200 空表而不是 404（初稿曾让缺席走 404、与 `/api/board` 缺文件同款，落地前改掉）：web 对两者的处置完全一样 = 空层，没有第二种含义要靠状态码区分；新装机 / 从未 harvest 时文件不在是常态而不是错误（宪法第 11 条），404 envelope 还会把 `$AIASSISTANT_HOME` 的绝对路径带给客户端；坏文件的 ETag 照发，客户端缓存空表直到文件换版——与原生「corrupt → layer absent」同义。(3) `Cache-Control` 用 `no-store` 而不是 `no-cache`：与全部 API 读面一致，条件请求由 web 自己带 `If-None-Match`，不引入浏览器 HTTP 缓存这第二层。(4) 重验节律 = 「搜索开着时每版看板落地」而不是定时器：web 没有原生 ~10 s tick，看板落地（SSE `board.updated`）就是 actd 跑过一个 pass 的信号，索引也只在 pass 里改；搜索清空期间不重验，再搜时带旧 ETag 补一次。(5) 章自己从 store 算、不由 BoardLanes 逐卡传 prop：五种卡组件本就订阅 store（`MergeStateChip` 同款），一颗自包含的 chip 比给五个组件各加一个 prop 少一条传参链；匹配本身在 `pick` 里已算过一遍，chip 再算一遍是 per-card 一次 haystack 归一化——原生的 memo 是为 SwiftUI 每帧重算防御，React 这里由 re-render 边界兜。
