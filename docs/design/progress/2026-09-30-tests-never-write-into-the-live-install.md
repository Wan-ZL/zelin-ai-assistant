新法 §82 一句话：**跑测试的进程永远不许把一棵 git 工作树当成 `AIASSISTANT_HOME`**。判据不看 env 有没有设（那条的逆命题不成立，而且真安装本身就是一棵 clone，「env 缺席即拒」等于把回落值对每个用户永久作废换来零安全），也不看路径白名单（`ci-nightly.yml` 给的 `${{ runner.temp }}` 不在 `$TMPDIR` 底下，而 `.github/workflows/` 改不动），而是「解析掉所有符号链接之后，它自己或某个祖先有没有 `.git`」——与 §74.1 的 `.pkg` 目的地守卫逐字同源，因为两次事故的入口都是符号链接。守卫住 `act/lib/home.py`，在 `HOME = _home()` 的下一行执行：11 个路径常量还没有一个被下游 34 处模块级常量抄走，进程里也还没有任何一次写盘。跑者判据是 `sys.modules` 里有没有 `unittest`/`pytest`——runpy 先装跑者模块、之后才 import 测试模块，所以它与 import 顺序无关；零误伤的前提（act/ 与 server/ 全树没有一行 `import unittest`）写成了判例。拒绝本身继承 `BaseException`：房内为同一个问题立过一次法（`tests/__init__.RealSubprocessBanned`），理由一字不差——生产代码遍地是 `except Exception` 的 best-effort 兜底，守卫要是能被吞掉就等于没建。这条是复核时实测出来的：它原本是 `RuntimeError`，`import server.settings` 在 live home 上 rc=0，`skill_store` 静静变成 `None`，进程带着 live 路径跑完，看起来像产品少了一块能力，不像 home 出了事。

同批三件配套：33 个漏网文件各加一行 `from tests import TMP_HOME`（守卫是拒绝，这一行是让它压根不发生——开发者单独跑一个模块从此照样沙箱化），`run_gates.sh` / `run_coverage.sh` 改成**无条件**开一次性沙箱（写法被判例钉成两条语句：`export X="$(mktemp -d)"` 会触发 shellcheck SC2155，而 CI 的 lint job 对每个 tracked `*.sh` 跑裸 shellcheck），`ingest/vault-sync.sh` 把 `AIASSISTANT_HOME` 钉成 `:?` 前置条件（它的 pull 是 `rsync --delete`，空变量会让目的地塌成 `/state/vault-mirror`——今天安全只是两个 sourcing 脚本先设了值的巧合）。防回退靠 `tests/test_sandbox_isolation.py` 的 ast 全树扫描，零豁免、零 shrink-only 账本：同一个 PR 里修得完的事不配拥有一份欠账台账。扫描器递归看 import 期会执行到的每一个 import、只在函数/类体前停：只认 `tree.body` 的直接子节点会让 `if _LANDED:` / `try: … except ImportError:` 里的 import 整份隐形——那不是判它违例，是压根不查，而一个隐形豁免比一条明账更糟（这一条同样是复核时补上的）。

事故的第二半是假时钟戳（§82.4）。`state/slack_mcp.marker` 被写成 `2027-10-23T11:32:23Z`，于是 `now - marker` 是负 timedelta、`< interval` 恒真，Slack MCP 雷达直到 2027 年都答「还没到点」。治法是给房内既有的 ISO 解析器 `maintenance.parse_iso` 加一个 add-only 旋钮 `reject_future`（出厂关），接线三处：MCP 节流戳、用**文件 mtime** 当时钟的 MCP 存在性缓存（未来 mtime 让缓存永不过期），以及 doctor 的 dashboard 行——未来 `generated_at` 此前让 `max(int(age), 0)` 把一块死看板印成 `fresh (generated 0s ago)`，是宪法第 3 条的活违例。`dashboard_stale` 这个 failure_id 沿用不新增：症状不同而修法逐字相同，新 id 会连带拖上 `mac/Sources/Doctor.swift` 的 FailureCatalog 漂移判例，收益为零。凡是未来值只会让系统更保守的读者（`purge_due`、deadline 判决）一律不碰。接线本身埋了一颗：把解析从 `try` 体挪进 `parse_iso` 时，`_read_mcp_marker` 的兜底被顺手收窄成 `except OSError`，而 `read_text(encoding="utf-8")` 在非 UTF-8 字节上抛的 `UnicodeDecodeError` 是 `ValueError` 的子类——一份被撕坏的 marker 从此不是「读不出」而是把 launchd 那个 3 分钟 tick 整个崩掉（宪法第 11 条）。复核实测抓到，改回 `except (OSError, ValueError)`；顺手补上 `_slack_mcp_present` 那一处早于本轮就存在的同款洞（它的 docstring 写着「Never raises」）。两条判例各自做过 revert-probe：把兜底收窄回去，它们立刻以 `UnicodeDecodeError` 报 ERROR。

留在 live `state/` 里的那批字节则交给一把扫帚 `python3 -m act.lib.state_audit`：默认只看不动，`--apply` 把命中的文件整份**搬**进 `state/backups/quarantine-<UTC 时间戳>/`（sha256 manifest、同名永不覆盖、搬错了 `mv` 回去）。绝不 `unlink`——2026-09-18 之后再做一次不可恢复的自动删除，等于用同一种病治病（宪法第 2 条）。这条差点被自己破了：第一版把文件拍平到 basename 搬，而 `state/` 是一棵树，`inbox/R-237.json` 与 `fold_receipts/R-237.json` 同名，`shutil.move` 在 POSIX 上退化成 `os.rename` 把后一份静静盖掉前一份，manifest 还照记两行两个 sha256——回执在撒谎，而且那正是本条禁止的那次不可恢复删除换了个入口（源文件名恰好是 `manifest.json` 时更直接：回执自己销毁了被隔离的那一份）。改成按原相对路径铺开，三条判例钉住。失败也照实说：建不出隔离区、某一份搬不动、回执写不下去，此前只存在于 `--json` 那一面，人看的那面一个字不说还反过来劝他 `re-run with --apply`（宪法第 3 条）。`work_seq.json` 与 `store2_truth.json` 只上报：夹具卡 `R-8150` / `R-960` 被工号分配收养这件事按 §60.2 改不回来，报出来给人看，不许悄悄「修」。决策按 owner 常设授权代拍（「所有我希望有的功能全部都推进到完成」，2026-09-06），记作 **D87**。取号过程本身值得记一笔：本轮起草时 §78–§81 与 D80–D83 正被四个在审草稿 PR（#459 / #461 / #462 / #463）占着，于是先取了 D84；随后它们连同 issue #440 的 recap 那批一起并进 dev，D84（recap）与 D85（`ui_scout`）落地，集成时把本节改号成 D87——本文与 CONTRACT 同步跟上，省得同一节法在两条分支上挂着两个号（§ 号本身不动：§82 在 dev 上也是 §82）。

## 复核回合二：全套门绿了之后的九个缺陷

第一轮复核（48 个 agent 的对抗式审查，43 条指控 7 条活下来）修完、CI 十一项全绿之后，又开了两个 fresh-context 复核 agent 逐面读整份 diff：一个只看正确性，一个只看法条与文档的自洽。它们**独立地**撞上同两条（报告模式那句空劝告、ast 扫描器跳过类体），另各带回四条与两条。九条全是真的，逐个带判例修掉，每一条都做了 revert-probe：把修法撤掉，指定的那条判例立刻红。

最实在的四条是代码：

1. **`_scannable` 的 `is_file()` 会抛**。pathlib 的 `_ignore_error` 只咽 ENOENT/ENOTDIR/EBADF/ELOOP，**EACCES 是往外抛的**，而这个逐份判决跑在 `_candidates` 那个 `try` 之外的列表推导里。真实形状是一个 `chmod 0444` 的子目录——列得出、stat 不了；`0000` / `0111` 反而没事，因为那两种 `rglob` 自己就列不出来。于是一把把「永不抛」写进 docstring 的诊断扫帚，能因为一个权限怪的文件整轮变成 traceback。同一条复核还指出本轮**删掉了**唯一一条从 `report()` 端到端打列目录失败的判例（换成了对 `_candidates` 的单元探针，够不到上层），所以两条都补了端到端版本。
2. **`"backups" in path.parts` 比的是整条绝对路径**。home 住在任何一个叫 `backups` 的目录底下（`<…>/backups/aiassistant`，完全正常的路径）时，`state/` 里每一份文件都被当成隔离区跳过，一棵脏树报成 `scanned=0` 的**干净**——虚报健康，而这正是这把扫帚存在的理由（宪法第 3 条）。改成数 `path.relative_to(state_dir).parts`，「隔离区里再深的嵌套下一轮也不重扫」这条老保证也另有判例钉住，没跟着丢。
3. **隔离区选名的 `for n in range(2, 100)` 是掉出去的**。99 个同秒候选全被占掉时，它带着一个**仍然存在**的目录回去，`mkdir(exist_ok=True)` 照样成功，于是这一轮搬进上一轮的隔离区、连 manifest 一起盖掉。够到那儿要同一秒 `--apply` 99 次，实际到不了——但 §82.5 的「永不覆盖」是无条件的，而且铺开 `rel` 之后盖的是同名**相对路径**，正是本轮刚禁掉的那次不可恢复删除。现在报「建不出隔离区」，`mkdir` 也收成 `exist_ok=False`，让「搬进一个已经有东西的隔离区」在结构上不可能。这条的 revert-probe 有个细节值得记：两半各自都能独立阻止覆盖，所以只撤一半判例照样绿——必须两半一起撤才复现，撤了就 ERROR。
4. **ast 扫描器把 `ClassDef` 一起跳过了**，注释里的理由写的是「函数/类体里的懒 import 发生在 env 立起来之后」——可**类体是 import 期就执行完的**，那个理由对它根本不成立。这就是扫描器自己声讨的那种隐形豁免，只是换了一个节点类型。全树 586 个模块今天零命中，所以是趁空收掉而不是修一条活的红线。附带一条反向账：递归进 `if` 体之后它开始数 `if TYPE_CHECKING:` / `if False:` / `if __name__ == "__main__":` 里那些 **import 期跑不到**的分支，而 §82.2 是零豁免零账本、被误判的人连出口都没有，所以这三种静态认得出的死分支减回去（`else:` 那半边照样算；`except ImportError:` 的处理体也照样算——try 失败时它就在 import 期跑，保守一侧）。

另外五条是文档与法条自己的不诚实，同样得改，因为法典是这个 repo 的真源：

- 一条**并不存在**的判例：§82.2 与 `act/lib/home.py` 都写着「十二个生产入口 import 完 `sys.modules` 里一个都不在」。真有的那条判例是对 act/ 与 server/ 全树逐文件**扫源码文本**，没有一行 import 测试跑者；运行时那一半**在进程内根本不可证**——跑判例的进程自己就在 unittest 里，`"unittest" in sys.modules` 恒真。要证得逐个入口起子进程（属 `tests/integration/`，防腐 #7 禁止 unit/behavior 层起真 subprocess），今天没有。「十二」还是个无源字面量，`act/` 单独就有 43 个模块带 `__main__` 守卫。改成照实写它证了什么、为什么另一半证不了。
- 一条会把自己读反的法条：§82.4 写「这三处…兜底必须继续写成 `except (OSError, ValueError)`」，而第三处 `act/lib/checks/pipeline.py` 的 dashboard 行本来就是更宽的 `except Exception`。照字面执行等于要求把一条诊断行**收窄**——与本意正相反，而且同一段两句之后自己就写着「两处各有判例」。改成：约束是**下限不是字面量**，radar 那两处写成 `(OSError, ValueError)`，dashboard 那处保持 `except Exception` 且不许按这条收窄。
- 一个手写数字：「live 那份 4.8 MB」。当天实测 4,902,912 字节 = 4.90 MB / 4.68 MiB，两种读法都不是 4.8，而且这个文件每一轮都在长——防腐 #5 正是禁这种手写字面量。换成指向 `MAX_READ_BYTES` 的 truth 指针。
- 两处仍按**拍平布局**写的「同目录留 `manifest.json`」（§82.5 与模块 docstring）：本轮把文件改成按 `rel` 铺进子目录之后，回执与它们已经不同层了——而那个「不同层」恰恰是源文件名叫 `manifest.json` 时挤不掉回执的原因，写错就把论证抽掉了。模块 docstring 还把 manifest 记的「原相对路径」写成「原路径」。
- `act/radar_slack.py` 的模块 docstring 没写 §82.4（防腐 #5 要求模块 docstring 点明管它的法条），而本轮恰好又往它身上加了两处 §82.4 管的行为。

第一轮那 43 条指控里被驳回的 36 条没有跟着改，理由也记一笔：最值得一提的两条是「把 `dashboard.json` 加进扫描白名单」（会让这把扫帚对它存在的理由那一类伤害正好失明）与「`docs/design/vnext2-plan.md` 缺 D87 行」（现状如此——main 上的 §77 引 D79 也没有对应行，而五个并行 PR 同时往同一张表尾部追加等于保证冲突）。
