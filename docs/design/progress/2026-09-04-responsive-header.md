**做了什么**：owner 截图里 52px 定高的 sticky 顶栏（grid `auto 1fr auto`）中缝装着 `flex-wrap: wrap` 的 FilterBar，窄窗口时搜索框 + 五颗 chip + 提建议 / 选择 + 排序 叠成四行、上下溢出压住标题、每日整理条与页面。三个候选——加高换行、横向滚动、收纳——只有收纳不破坏「顶栏是一根定高的条」这条原生形制，于是按实测宽分三档。**为什么量顶栏不量视口**：顶栏宽 = 视口 − 导航栏，导航栏 48 / 200 / 160–320 可折可拖，同一视口下能差 270px。**为什么阈值是 token 而不是「装不下就收」**：装不下再收会在阈值附近来回抖（收起后左右两翼变窄 → 又装得下 → 展开 → 又装不下），而且 jsdom 量不出布局、没法判例；固定阈值 + 两个**静态**加项（壳桥在场 +180 / 英文 +200，只取决于桥与语言）+ 乘 `--text-scale` 覆盖了实测里全部会让内容变宽的因素（1440×900 golden 条件：zh 浏览器 full 内容 ≈ 1030–1105、壳 +180、en +200、compact ≈ 730 / 900）；预算按左翼只剩标识 + 标题算（review 后：左翼小字省略号让位，见下）。**三档**：full 原样；compact 把 Tier / 期限 / 回锅 / 排序 / 清除 / 选择 收进「筛选 · N」按钮的 popover（`FilterPopover`：`role="dialog"`、焦点进面板 / Tab 循环 / 还给按钮、⎋ / 点外面 / 视口变化关；TaskPropertyPicker 的 listbox 本就 portal 进最近的 `[role='dialog']`，所以子弹层天然算「里面」、⎋ 先关子弹层再关面板）；tight 搜索折成放大镜（点它 / ⌘F 展开成行内框、失焦收起、有词带点）、筛选 / 提建议 / 录制 / 实时字幕 只留图标（aria-label = 全档文案，录制状态词挂 title）、左侧只剩标识 + 标题、新鲜度 / 部署小字折进连接点 tooltip（陈旧 / 非 healthy 时点转橙）。FreshnessLabel / DeployLabel 拆成 hook + 渲染两半（HeaderBar 调一次 hook、按档位决定渲成标签还是折进 tooltip，不多起 interval）。

**review 后修的四处**（#206 review）：(1) `.chrome-search` 的 `flex: 0 1 200px` 收进 `.chrome-filterbar .chrome-search`——回收站 / 永久性完成 / 设置页复用这个类，容器竖排，basis 在那儿变成了 200px 的**高度**。(2) 静态阈值不看左翼内容，而左翼在「陈旧新鲜度 + 已回滚部署 + 设备标签」时能长 ~400px，槽位（原 `1fr` + `overflow: hidden`）就把 清除 / 提建议 / 选择 / 排序 静默裁掉了；改成 grid `minmax(0, auto) minmax(max-content, 1fr) auto`：槽位下限 = 自身内容，左翼先让，设备标签 / 新鲜度 / 部署小字 `min-width: 0` + 省略号（全文挂 title，警告色照留；设备标签是机器名、长度不可预算，所以也得让），阈值预算按左翼只剩标识 + 标题算——不引入「装不下就收」的抖动源。tight 展开的搜索框改 basis 0 / `min-width: 0`：吃余量、不参与槽位下限，en + 壳 @720 也不再左右各裁 14px。(3) tight 搜索框展开着点「筛选」/「提建议」：mousedown 的 blur 先收起搜索框、居中的图标行重排，mouseup 落空，第一下点击丢——`.chrome-filterbar` 的 `onPointerDownCapture` 在 tight + 展开时对非输入框目标 `preventDefault`（焦点不走、不重排；WKWebView 点按钮不给焦点，`relatedTarget` 靠不住），「筛选」的 click 顺手收起搜索框（同一次渲染，popover 量到的锚点是最终位置）。(4) 与 main 的 D29 / D30 行冲突 → rebase，D29 / D30 / D31 按序保留。
