**做了什么**：审计对照退役原生 `mac/Sources/Store.swift` `SlashCommands` 与 `Composer.swift`，web 列顶输入框（`composerCommands.ts` / `LaneComposer.tsx`）丢了五处行为，本批一次补齐。(1) **闸门**——原生 `isCommand` 是 `^/(rec|open|lang)\b`，源码注释明写「/Users/… 整理一下 是普通捕获」；web 曾把任何 "/" 开头的草稿都当命令、动词不认识就报「未识别或参数错误：」，路径捕获永远发不出去（scratch 复现：`runSlashCommand('/Users/zelin/x 整理一下')` → unrecognized，`postAction` 不被调）。现改为 `^\/(rec|open|lang)(?=\s|$)`（`i`）：非三动词 → `handled:false` 走普通捕获；用 `(?=\s|$)` 而非 `\b` 是因为 JS 的 `\b` 只认 ASCII 词字符、「/rec整理」会被误判，原生 ICU `\b` 是 Unicode 词界；动词不分大小写是 web 放宽的一点超集。删掉不可达的 `default:` 分支。(2) **词表**——`/rec` 补回原生词 `audio`（Map 别名 → 壳的 `screen_audio`，避免对象原型键蒙混）、参数 `lowercased()`；`/open` 补回 `deps|ingest|about`（原生 MainSection 五页排前、web 独有页排后；`deps` 落 D30 的设置页依赖检查区）；用法句从同一份表派生。(3) **提示行**——导出 `hintLine()`，草稿以 "/" 开头时在输入框下渲染一行 `.column-help`；列的是 web 完整词表（原生词在前），不是原生字面量逐字——超集只列一半就是撒谎。状态栈与原生同形：失败句 > 提示行 > 成功回执；原生栈底的键位提示句已随 D35 退役、不补。(4) **一改字失败句即清**（原生 `.onChange(of: text) { slashError = nil }`）。(5) **title = 原生 `.help`**——直跑「直接开跑：跳过提案与费用预估，成果仍进「待验收」」；捕获「快速捕获（<快捷键>）」：原生写死 ⌘L，web 只在壳里有全局快速捕获键（壳快照 `hotkey`，今日 ⌃⌥Space；`useShellState`），浏览器里没有键就只写「快速捕获」——不谎报。身份（propose / run）从 `buildBody` 的 payload 读（`mode:"run"`），不加 prop、不动 `BoardLanes.tsx`（board-lanes chain 另一批在改它；后续 `composer-receipt-honesty` 批也要按 mode 选回执句，可直接复用 `composerMode`）。
