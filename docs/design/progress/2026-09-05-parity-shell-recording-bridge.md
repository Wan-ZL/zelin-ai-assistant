**做了**：(1) **TCC 提示回到「开启」前**（gap `recording-captions-consent-turn-on-no-tcc-prompt` + `diagnostics-setup-consent-turn-on-no-tcc-request`）：原生三处「开启」——`Onboarding.record`、`Permissions` 状态行「开启(…)」、`SetupWizard` 终章「启动引擎」——都是 `if !RecordingController.hasScreenPermission() { RecordingController.requestScreenPermission() }` 再 setMode；web 移植后 consent「开启」只发 `setRecording`，桥直接 setMode，引擎没授权就立刻退出而页面看不到系统提示。改在桥（`ShellBridge.swift` 新 `RecordingActions.turnOn`）而不是三个 web 调用点：一处补、页面不用管 TCC；`CGRequestScreenCaptureAccess` 每个身份只弹一次所以每次开都调是安全的。`Recording.swift` 是逐字节冻结副本（§61.3 判例），缝只能长在它外面——`RecordingActions` 四个静态闭包（hasScreenPermission / requestScreenPermission / setMode / refresh）默认直连引擎，harness 换假实现，首次能在不 pkill 真 screenpipe 的前提下钉 `setRecording` 合法参数的顺序（缺授权：request → setMode；有授权：只 setMode；on:false：只 setMode(off)；被拒：两者都不碰）。(2) **`refreshRecording`**：pollScreenPermission + refreshEngineState 一次（5 s tick 的两步），回执起跑后的快照；`getState` 保持纯读（`startShellBridge` 连上就拉它）。(3) **快照 add-only 七键**：`recording.self_heal_note` / `log_tail`、`captions.translation_note` / `translation_active` / `source_note` / `apple_engine_available`、`permissions.screen_requested`——原生录制 / 字幕设置区 / 权限行还在用、web 尚未拿到的值；`shellBridge.ts` 类型 optional + `normalizeShellState` 补 `""` / `false`（老壳不崩、既有 fixture 不用改字）。(4) **悬浮窗 frame 迁移**（gap `recording-captions-overlay-frame-not-migrated`）：`LegacyPrefs` 补搬 `NSWindow Frame liveCaptionsPanel`，独立一次性标记 `legacyOverlayFrameSeeded`——owner 在用的壳（`legacyPrefsSeeded` 早已 true）也补收一次；壳自己拖过的不覆盖。
