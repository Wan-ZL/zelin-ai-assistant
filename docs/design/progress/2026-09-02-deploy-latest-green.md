law: §56.3 第 3 步「合并风暴下的部署目标」（新增段）/ 第 2 步追记 / §56.4 `behind_main` `behind_main_why` `failed_shas` / §56.5 中毒账本改集合

**事故 2026-09-03T00:38Z→01:18Z**：本轮并行 PR 每 10–20 分钟合一个，`ci`（macOS job）在 Actions 队列下要 20+ 分钟；`scripts/auto-deploy.sh` 每 10 分钟只看 origin/main 当时的 head，五轮连续「CI not green yet on <越来越新的 sha>」，而 v1.0.4–1.0.6 各自绿着、tag 也铸了，躺在 head 后面几小时没有一个上机。只看 head 的闸门在**合并密度高于 CI 时长**时必然饿死——这不是 CI 慢的偶然，是 §56.2「merge = release = deploy」与 §56.6 并行 PR 自动跟随 main 合起来的常态形状。

**做了**：(1) head 不绿（pending / 红 / 已中毒）→ `latest_green_ancestor`：沿 first-parent 从 head 往回走（`git rev-list --first-parent --skip=1 --max-count=$AUTODEPLOY_CI_WALK PREV..head`，默认 30，每个候选再 `merge-base --is-ancestor PREV` 复核），部署最新的一个 `ci` 已 `completed` + `success` 的 commit——它是曾经的 main head、PREV 的后代，第 5 步 `merge --ff-only` 仍是 fast-forward，下一轮从新落点继续向更新的绿走；红的祖先当场中毒 + 一条「main 的 CI 红了」通知、以后不再问；没有 `ci` run 的 commit 是 pending 不是绿（CI-diet 的 path filter 不会造出假绿）；走完没绿 → 按 head 的判定落 `ci_pending` / `ci_failed` / 只写 `last_run`，detail 列出走过的每个 sha 与判定。(2) 中毒账本从单槽 `failed_sha` 扩成集合 **`failed_shas`**（镜像私账、上限 `AUTODEPLOY_CI_WALK`、与 `failed_sha` 同进同出）：单槽在回走下会成环——红 head H 中毒 → 部署祖先 G → G 回滚（槽 := G）→ 下轮 H「不在槽里」再问再通知、G 再部署再回滚，每 10 分钟一次；判例把这个环钉死。(3) `deploy_state` add-only 投影键 **`behind_main` / `behind_main_why`**（上一次部署停在 head 之前时记被跳过的 head 与原因；部署到 head 或 `up_to_date` 清，回滚不碰），doctor `auto-deploy` 行 OK 时追加「origin/main <sha> not deployed: <why>」，web `DeployState` 类型逐字镜像。(4) 既有闸门一条不动：failed_sha 中毒按实际部署的 sha 记、回滚先停 actd 再采样、stamp 版本身份、blocked_tcc 探针、`--force` 只认 head 且跳过闸门与回走。(5) API 预算：无认证 60/h；每轮 = head 一次 + 每个仍 pending 的祖先一次（红的中毒后不再问、绿的当场部署），实战形状 ≈ 20/h，`AUTODEPLOY_CI_WALK` 硬上限，撞限 = pending 下轮再试。(6) TROUBLESHOOTING 新节「合并很密的时候自动部署几小时不动」。

**判例**：`tests/integration/test_auto_deploy_script.py`——newest red + older green → 部署 older、head 保持中毒、下轮零 API 调用零通知 / 全红 → 不部署、每个红 sha 通知一次、下轮零调用、绿的新提交清整本账 / head 绿 → 部署 head 不回走 / head pending（含「没有 run」）→ 部署祖先、下轮 `ci_pending` 只问 head 不重装、head 绿后追上并清 `behind_main` / 回滚过的祖先在 head 仍红时不再重部署（两轮零调用零安装）、`--force` 仍只认 head / 回走有界（`AUTODEPLOY_CI_WALK=2` 越界的绿不问）；`tests/test_deploy_state.py`——`behind_main` 投影、`failed_shas` 不投影、OK 行文案。整套 85 条仍在 300 s 预算内。

**没做**：不把回走结果投影成新的 status 词（`deployed` 就是 deployed，机器跑的是最新被测过的代码；main 领先由 `behind_main` + doctor 行说）；不缓存 pending 判定（pending 就该每轮再问）；不改 §56.3 成法「一次部署跑的是合并前的旧脚本」——本 PR 自己上机那一轮仍由旧闸门守，head 绿了才动。
