law: §48.4 追记（`radar_sources.<src>.intent` / `secret_present` add-only；web 资格判据；首见台账修剪）；§66 追记「enabled 即 intent」一句加修正注

**为什么**：审计对照原生 Diagnostics.swift / DiagnosticsRules.swift 发现 web 诊断条丢了两条 anti-nag 行为。(1) 原生 `gmailCardEligible` 对 setup 类 reason（no_credentials / no_address）要「真实意愿信号」——用户碰过开关（overrides 里有 `gmail_enabled`）或凭证文件存在；Slack 的 `connect_failed` 只在 token 非空时出卡、`mcp_not_configured` 只在 secrets 文件存在时出卡。web 版（#188 落地时）把 `enabled` 当成 intent，而三源开关默认全开、雷达在空白机上如实报 no_credentials / mcp_not_configured——D25 验收路径的看板因此常驻两张卡，dismiss 只安静 7 天；那条「fresh user 零卡」判例靠 `enabled:false` 才过，判的根本不是这件事。§66 追记里「`enabled` 即 intent」那句与 §48.4 正文（「enabled 默认 true」本身不是 intent）直接相悖。(2) 原生 `pruneFirstSeen(keeping: liveSignatures)` 每次重建都把不再活着的签名从首见台账里忘掉；web 的 `diagnosticsFirstSeen` 只增不删——录制关几天再开，几天前的时间戳让 vault_empty 立刻告警，35 min 预热只在有生之年的第一次有效。

**做了什么**：意愿信号搬进 actd 投影（web 没有文件系统，§44 单写者，server 只读转发）：`act/lib/dashboard._source_signals` 给每源条目追加 add-only 两键。`intent` = overrides 里存在 `<src>_enabled` / 嵌套 `features.<src>_radar` / 平铺 `"features.<src>_radar"` / 手写 `<src>: {enabled}` 任一（config `_apply_settings_overrides` 认的拼法都算，开或关都算碰过）∨ §19 凭证文件存在（空文件 = 配到一半）∨ 凭证非空；obsidian 的「配到一半」= `obsidian_raw` 指定过。`secret_present` = §19 凭证非空——读 `config/secrets/<name>` 与 config.yaml 显式路径（非缺省值），**不读**已弃用的旧默认路径 `~/Desktop/Keys`（原生 `SecretsIO.hasSecret` 也只看 config/secrets；顺带不让每个 dashboard 构建去 stat owner 的桌面、不让测试套件碰真凭证）；obsidian 恒 false。坏 overrides / 探针异常 → 两键 false，投影不崩。web `DiagnosticsStrip` 导出 `gmailCardEligible` / `slackCardEligible`（原生逐条：setup 类要 `intent !== false`、`disabled` 永不出卡；Slack token 类要 `secret_present !== false`、`mcp_not_configured` 要 `intent !== false`），键缺席 = 旧 payload = 老判据；`agent_missing` 不看信号、让位规则不变。首见台账：导出纯函数 `pruneFirstSeen(seen, live)`，组件在遍历完 `buildDiagnosticCards` 的全部结果（预热 / dismiss 之前）后修剪再落 localStorage，无变化返回同一对象。`types.ts RadarSourceHealth` add-only 两键。golden `tests/fixtures/dashboard_golden.json` 随 add-only 键**刻意重铸**（fixture 里 gmail 碰过开关无凭证 → intent 真 / secret 假，slack 有 token → 双真，obsidian 双假；overrides 与 secrets 目录都钉进 fixture 的 state_dir，不吃共享沙箱）。CONTRACT §48.4 追记一段；§66 追记那句只加修正注不删字。

**没做的**：不动 Swift 壳 `Contract.swift`（全 decodeIfPresent，新键自然忽略）；不改 server（投影透传）；不把 web 设置页的 diff-write 改成原生那种「两个方向都落键」——用户翻开又翻回默认时键被删、intent 回落到凭证文件判据，这是 §68.1 diff-write 的既定语义，本批不碰；`agent_missing` 的 2 min 预热（原生 `agentMissingWarmupSeconds`）不在本批 gap 里，仍未搬。

**判例**：`tests/test_dashboard_source_intent.py`（15 条：全新安装三源皆 false / 四种开关拼法 / 关掉也是碰过 / 无关键不算 / 空凭证文件 = intent 非 secret / 非空 = 双真 / 显式路径算、缺省旧路径从不被读 / obsidian vault / 键序 add-only / 关着的源照算 / 坏 overrides 与探针异常不崩）；`tests/test_dashboard_golden_projection.py` 加三源信号断言；既有 `test_sources.py` / `test_dashboard_helpers_edge.py` 的键集合断言加两键；web `DiagnosticsStrip.intent.test.tsx`（两张资格矩阵 / 全新安装零卡、碰过开关出卡 / 无 token 的 connect_failed 静默 / 连接类不看 intent / 旧 payload 老判据 / agent_missing 不看信号 / pruneFirstSeen 纯函数 / 组件级「消失再出现重新预热 35 min」与「活着的签名一分不动」——去掉修剪那一行判例即红）；`DiagnosticsStrip.test.tsx` fresh user 判例改成 `enabled:true + intent:false`。
