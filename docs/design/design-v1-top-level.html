  • 一句话定义：把「Arash（或任何会议/Slack）说过的每一句需求」变成「第二天早上等你 review 的 draft PR / 实验报告 / 训练结果」，而你只需要在手机上点 ✅ 或 ❌。

分级审批：不是所有事都值得一次点击

为什么要分级：你说"所有 LLM 检测到的都做太浪费"——反过来，如果每件事都要你点一下，你一天要点 30 次，审批就成了新的瓶颈。解法是像机场安检分快慢通道：无害的自动放行，普通的一键批，烧钱/有风险的要看明细。
级别范围你要做什么例子

App 产品形态（顶层）

单 repo 三层结构——引擎与壳分离，没有 UI 引擎也能独立运行（这保证 v0 本周就能用）： 
overkill/
├── core/          # pipeline 引擎: 雷达/注册表/提案/执行调度 (CLI, 无 UI 依赖)
│   ├── prompts/   # 各环节的 Claude prompt 模板
│   ├── registry/  # 需求注册表 (YAML, git 版本控制)
│   └── config.example.yaml   # 监控源/审批阈值/预算线 (配置与代码分离)
├── mac/           # Mac 完整版: menu-bar app = 仪表盘+注册表浏览+审批+配置+依赖向导
├── ios/           # iOS 轻量版: 查看提案卡 + ✅/❌/💬 + 推送
├── install.sh     # 一键安装: 检测 claude/gh/obsidian/jira → 缺什么引导装什么
└── docs/

三条硬原则

  • 本地优先：所有密钥、会议记录、公司数据只存在于你的 Mac；执行也全部发生在 Mac 上。
  • iOS 端永不持有密钥：手机只接收提案卡片、回传 ✅/❌/💬 三种决定，是纯"遥控器"。
  • 配置与代码分离：同事 clone 后跑 install.sh，填自己的 config（自己的 Slack 频道、自己的 vault 路径、自己的 Jira 项目），依赖缺失时向导提示安装——Obsidian/screenpipe 没有也能跑（少一个源而已，源是插件化的）。

你没考虑到的 8 个点

1 · 审批要分级 + 成本预览

一次点击不能同时授权 $500 训练和一行 README 修改。卡片必须带成本预估——这也正是 Arash 对你的管理方式（"let me know the cost"），你只是把它产品化。

2 · 质量门是速度的前提

Arash 同一场会里说的另一半话："be most proud of the work"、"早点拿 external feedback"、"leaderboard 必须 truly representative"。没有自检门的自动化 = 快速产出垃圾 = 烧信任，和目标背道而驰。他 6/30 还在问 "Was this reviewed internally?"

3 · 证据回显防误听

screenpipe 单麦 ASR 会错（实录: "agent harm"→"agent hardware"）。如果 pipeline 根据听错的需求干了一晚上活，浪费远大于省下的。卡片回显原话 = 你点 ✅ 时顺手完成人工核实，零额外成本。

4 · 需求会演化、会跨源出现

AgentHarm 这一条横跨 7/1 会议 → 7/4 Slack → Confluence 草稿三个源。注册表必须做跨源合并与状态更新，否则你会收到三张重复卡片，审批疲劳三倍。

5 · 执行器要吃你的记忆

裸的执行 agent 会踩遍你记忆里的全部地雷（eval 路径 8 倍坑、loss≠capability、Fireworks 命名、数据目录规矩）。执行器启动时自动注入 program map + 相关约束——你已有的 auto-memory 正好是 pipeline 的知识库。

6 · 凭证寿命与静默失败

AWS SSO 90 天过期、OAuth token 失效、Crusoe VM 忘删。执行器必须能识别"这需要 Zelin 重新登录/决定"，DM 你而不是静默失败或蛮干。周报里列"卡住的任务"。

7 · 漏检兜底（谁看着雷达）

LLM 提取有假阴性——低置信度"疑似需求"不建卡片，但进周一 digest 让你扫一眼。宁可周报里多 5 条噪音，不可漏掉 Arash 的一句"顺便把 X 也弄一下"。

8 · 提速的真正来源

这个 pipeline 快在：捕获零遗漏、审批零摩擦、执行在你睡觉时并行跑（Arash 原话就在推 "parallel runs"）。你仍然在环上——Arash 要的是"第二天出结果"，不是"没人看过就出结果"。人不下环，是 feature 不是 bug。

三个要诚实说的约束

  1. 没有真·按钮推送：v0 的"点击通知"实际是：手机收到 Slack DM 推送 → 点开 → 按 ✅ emoji。体验相差无几，但不是 iOS 原生按钮（那是 v3 的事）。
  2. 审批生效有分钟级延迟：雷达是轮询制（默认 30 分钟一轮，工作时间可加密到 5-10 分钟）。你点 ✅ 后不是秒开工。事件驱动的即时触发留给 app 阶段。
  3. headless 下 MCP 认证待验证：Slack/Atlassian MCP 的 OAuth 在 launchd 进程里是否可用，要在 v1 第一次跑时验证；兜底 = Atlassian API token（Keys 里已有）+ Slack 改走 Jira 通知。
